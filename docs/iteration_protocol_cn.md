# 与 AI 迭代的格式（一页）

一个对话只处理一个问题。对话日志用 `MMDD-名称` 命名（`research-memory`）。

## 每一轮

1. **从终点倒推。** 沿用研究者确定的问题和资源范围，说明成功时会看到什么，以及本轮能改变其中哪一项判断。
2. **AI 主动提出猜想。** 说明看好它的理由、最强的竞争解释，以及哪一项比较会使两者给出不同预测。把它写成 `AI 建议`。若从现有结果跳到了更强的结论，指出中间需要成立的条件。
3. **进入实验时**，写下先验、由它推出的量、各结果对应的选择和算力。可执行代码、配置和启动方式保存在项目代码仓；探索日志链接版本和实际执行目录。在研究者批准的范围内运行。
4. **读结果时**，先对照跑前预测，再说明假设或推导的哪一步要改、为什么下一项分析优先。意外发现可以产生新猜想。研究者作出的选择写入 `log.md` 的“研究者决定”，尚待决定时记 `Unknown`。
5. 当天的 `今日认识更新` 写出现在懂得了什么，以及这个认识会怎样改变做法。

## 组会

从多个探索日志汇总组会材料时，可以运行下列命令。

```sh
python tools/meeting_digest.py research/<project>/main/explore --since MMDD [--until MMDD]
```

它把两次组会之间各探索日志里的“今日认识更新”和对应假设汇总成简报草稿（目的、结论、假设、实验分析）。草稿标为待研究者确认，不生成科学结论；保留 2–3 条最重要的结论并附上原始数据链接。

## 升级

只有要进入组会正式结论、论文或长期地图时，才按 `docs/formal_lane.md` 补正式记录，并引用探索日志里的原始数据。
