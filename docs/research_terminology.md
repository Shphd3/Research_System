# 全局研究术语表

本文件登记中文研究讲解中反复出现的英文代称。中文名称始终是阅读入口；英文代称只能在定义之后充当简写，不能代替研究对象本身。

## 使用规则

- `APPROVED` 表示该代称已经批准，但只能在登记的含义和范围内复用。
- 每一份新讲解第一次使用时，仍必须写成`中文名称（英文代称）：一句定义`。
- 完成首次定义后，同一份讲解才能单独复用该英文代称。
- 来源文档中的局部英文名称可以作为原文引用，但旁边必须给出中文含义，讲解不能直接把它变成未解释的简写。
- 未进入本表的重复性代称保持 `PROPOSED`；研究者批准全局映射前，正文使用中文。
- 单次实验编号、条件编号、方法名和符号放入该次讲解的“本次术语”，不因一次定义自动成为全局术语。

## 已批准的共有术语

| 中文标准名称 | 允许的英文代称 | 固定含义与使用范围 | 不能自动等同于 | 状态 |
|---|---|---|---|---|
| 公共成分 | `common` | 一个角色词：在已声明判据和范围内，被多个对象共同包含或共享的部分。每次首次定义必须同时说明它是表示公共成分还是功能公共成分，以及范围是全局、节点、任务还是样本集合。只有功能证据存在时才能进一步称为“共同需要”。 | 固定公共向量；均值；高频成分；祖先专家全部输出；未经验证的功能必要性 | `APPROVED` |
| 专门成分 | `specialized` | 一个角色词：在已声明判据下，与特定条件、分支或任务相关而不被全部对象共享的部分。每次首次定义必须区分表示专门成分和功能专门成分；只有功能证据存在时才能称为该条件所需要。 | 低频成分；细粒度标签；必然有专家收益；未经验证的功能必要性 | `APPROVED` |
| 专家模块 | `expert` | 混合专家模型中承担一部分条件计算的模块。 | 语义类别；固定标签；已经形成专门化功能的模块 | `APPROVED` |
| 混合专家模型 | `MoE` | 由路由机制选择或组合多个专家模块的模型。 | 层次结构；稀疏计算；有效专家分工 | `APPROVED` |
| 路由器 | `Router` | 为输入选择专家或输出专家分数的机制；若指离线读出探针，必须明确写出。 | 专家本身；真实专家效用；标签分类器的必然部署形式 | `APPROVED` |
| 分类间隔 | `margin` | 样本相对决策边界的有符号距离或分数差；使用时必须说明具体公式、是否归一化及统计分位数。 | 准确率；类别距离；专家功能收益 | `APPROVED` |
| 下一词元预测 | `NTP` | 根据已有词元预测下一个词元的训练任务。 | 特定训练算法；公共成分优先学习的既成结论 | `APPROVED` |
| 主成分分析 | `PCA` | 按样本方差寻找正交方向的线性分析方法。 | 语义发现；专家效用发现；因果机制 | `APPROVED` |
| 分布外测试 | `OOD` | 测试分布相对训练分布发生了预先说明的变化。 | 任意泛化；真实世界分布；更困难的数据 | `APPROVED` |
| 线性探针 | `probe` | 在冻结表示上拟合的受限读出模型，用于检查注册信息是否可访问。 | 模型原生使用该信息；因果使用；专家效用 | `APPROVED` |

## 必须带限定对象的术语

以下英文词单独出现时含义不足。必须先说明具体中文对象，才能使用英文代称：

| 不可裸用的英文词 | 允许的限定例子 | 原因 |
|---|---|---|
| `common` | 表示公共成分、功能公共成分、节点内公共成分 | 必须分开表示共享与功能共享，并声明适用范围。 |
| `specialized` | 表示专门成分、功能专门成分、节点内专门成分 | 必须分开条件相关性与功能必要性，并声明适用范围。 |
| `residual` | 表示剩余项、功能剩余项、更新剩余项 | 不同剩余对象回答不同问题。 |
| `nuisance` | 与当前标签无关的高方差干扰、模板干扰 | “无关”只相对于一个已声明目标成立。 |
| `split` | 数据分支划分、路由分支规则 | 需要说明划分对象、依据和用途。 |
| `Dense` | 稠密模型基线 | 需要说明架构、参数量和活动计算。 |
| `Flat MoE` | 平铺混合专家基线 | 需要说明路由输入、专家输入和活动专家数。 |
| `Tree` | 层次专家树候选方法 | 需要说明树节点、分支规则和路径计算。 |

## 待批准术语

只有预计会跨文档重复出现的英文代称才进入这里。候选项必须记录中文名称、预期含义、使用范围和最容易混淆的对象；研究者把状态改为 `APPROVED` 前，讲解继续使用中文。
