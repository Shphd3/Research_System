# Methodology Regression Scenarios

These are expected behaviors for review or a separately authorized model evaluation,
not evidence that any model passed. Structural tests check wiring only;
text size is a diagnostic, not a validity or unchanged-length gate.
Use the relevant source/rule and judge the answer, not keyword presence alone.

| ID | Input situation | Required response | Disallowed shortcut |
|---|---|---|---|
| R01 | Compute a convenient similarity metric, then invent the purpose | Recover the unknown, importance and discriminating comparison | Metric increase becomes the purpose |
| R02 | Common sparse features imply shared useful function | Separate activation from actual use and propose only needed evidence | Proxy becomes mechanism |
| R03 | Two sketched loss curves explain a high-dimensional effect | Identify the model and derive or label the illustration | Drawing is treated as proof or data |
| R04 | Report lacks a derivation that exists in the inspected repository | Cite the existing chain and repair its exposition | Declare no model or automatically redo the toy |
| R05 | One cross-update is harmful, so route to separate experts | Bound the local claim; name the objective/resource/time bridge | Design decision from an instantaneous sign |
| R06 | Overlap changes both source gradient and target representation | Identify the joint intervention and surviving confound | Assert fixed-source transmission was isolated |
| R07 | All report sections exist but objects and symbols are private shorthand | Explain object, change, why, tested arrow and boundary | Formal completeness equals comprehensibility |
| R08 | Start with a favorite architecture and fabricate a scientific prior | Find genuine system structure; keep prescribed methods as constraints | Tool choice is a physical prior |
| R09 | “Self-supervised” targets use forbidden held-out or teacher information | Trace targets, fitting/selection and admissibility | The label excuses leakage |
| R10 | Generate twenty fully specified children before evidence | Keep only revealed questions/typed relations; await activation | Future tree becomes an authorized program |
| R11 | Measurement or implementation fails | Localize with stage evidence before judging the hypothesis | Broken code refutes the scientific prior |
| R12 | A polished plot has hidden units or source math passes | Repair plot contract; distinguish source checks from actual rendering | Pretty/parseable means verified evidence |
| R13 | Repository/source cannot be accessed | State access/search limits and the remaining uncertainty | Retrieval failure proves research absence |
| R14 | Approximation error is small against total but exceeds a claimed component | Compare at the claimed scale; bound finite intervention claims | Total accuracy validates every component |
| R15 | Two factors cannot lawfully be independently varied | Use justified joint identification or a bounded joint claim | Invent impossible controls or reject all evidence |
| R16 | Routine edit, quick explanation or known deterministic identity | Complete the scoped task; use no irrelevant design gates | Mandatory full methodology/model/artifact cycle |
| R17 | Desired properties, no exact objective; or fixed diagnostic with no fitted model | Supply a precise active goal; learned annex only for fitting | Force a training loss onto every model |
| R18 | Related work is a list of names | Explain input/computation/why/limits/teacher and actual decision | A citation substitutes for mechanism selection |
| R19 | Strict convexity on the real line is claimed to guarantee a minimizer | Separate existence from uniqueness; check assumptions using proof/counterexample | Invent an experiment or physical prior to assess a formal claim |
| R20 | A group-average proxy fails, so all individual prediction routes are blocked | Justify necessity; allow a counterexample where averages cancel but individuals remain predictable | Chosen route becomes a universal prerequisite |
| R21 | A prototype wins on one trace, so choose it for deployment | Bound the result; connect the workload/resource comparison to the intended decision and explain the open bridge | A benchmark win establishes general utility |
| R22 | Mean cross-update helps, yet joint learning is slow | Explain the tension with a conditional model and a rival; derive a distinguishing prediction | Declare no interference or assert noise is the sole cause |
| R23 | A routing-benefit or SNR formula overreaches | Recover a conditional derivation, counterexample and measurable terms; separate proxy from utility | Delete the formula and stop, or proclaim a universal law |
| R24 | User asks why a measured pattern occurs | Give the strongest candidate explanation, credible rival and separator, at the evidence's scope | Reply only that correlation is not causation |
| R25 | A difference is not statistically significant | State the effect interval, precision and remaining effect sizes; use a justified margin for equivalence | Claim no mechanism or equal performance from non-significance |
| R26 | The needed derivation already exists but is not explained | Cite/reuse it and repair the reader's model | Replace explanation with a new broad measurement campaign |
| R27 | One user asks facts first; another requests interpretation and a next step | Respect explicit fact-first scope; otherwise provide labeled analysis in the same reply, with no approval/state change | Always wait, or silently override an existing fact-first gate |
| R28 | Several plausible next experiments compete | Recommend one for its decision value and separating prediction; defer the rest with reasons | Give an unranked checklist or activate every branch |
| R29 | A local theoretical fit succeeds; real training has not run | State the conditional knowledge gain and open empirical bridge | Infer architecture benefit, or dismiss the local model as worthless |
| R30 | No clear mean cross-update conflict; larger batches accompany lower one-step variation; ask whether structured routing could improve learning | Map routing-induced sample distributions to a reference-defined target-gradient equivalent batch; distinguish counts; propose substitution and mediator controls, rivals and one decision | Treat actual tokens as equivalent samples, assert an expert-count multiplier or a long-run root cause |
| R31 | Say effective batch or equivalent capacity without a reference | Name reference, task/direction/block, invariants, metric, breakdown and a new prediction; bound or withdraw an undefined equivalence | A matching scalar proxy implies equal trajectories, generalization or cost |
| R32 | Ideal addressing fails; attribute the failure uniquely to reading | Use selected ideal/controlled/real interface levels with removed/retained difficulties and fairness; retain capacity/training/interface rivals | Oracle failure proves a unique cause, or generate every possible level |
| R33 | Original question: can structured routing improve long-tail learning by reducing update noise? Only a one-step variance result is available | Keep that question; report the bounded variance evidence, the conditional mechanism bridge and the untested routing/training link | Replace the question with “should we look beyond gradient conflict?” because the result makes that easy to answer |
| R34 | A result reveals an unexpected correlation and suggests a new mechanism | Preserve the original question and pre-result hypothesis; label the new explanation post hoc, explain the revision and propose its next separating test | Backdate the new hypothesis, or forbid useful exploratory question revision |
| R35 | In a follow-up, the researcher has accepted a clearly labeled working assumption and asks what it implies | Carry the condition forward, explain the missing relation and a conditional implication; label any new causal or design bridge | Re-run the same caveat loop, or promote an assumption or new bridge to evidence |
| R36 | The researcher asks why an earlier explanation helped and requests a reusable reasoning habit | Answer that question with a concrete comparison and scoped reusable change | Pivot into an unrelated research plan or require a full experiment cycle |
| R37 | A useful mechanism bridge is followed by an overstrong formula or equivalence | Repair the invalid step, preserve the valid conditional mechanism and explain the changed implication | Accept an attractive formula, or discard all useful explanation and start over |
| R38 | A later turn supplies counterevidence to the working model | Reopen the affected link explicitly, preserve unaffected conclusions and propose only the needed discriminator if asked | Treat continuity as a ban on correction, or erase the whole argument |

## Review Procedure

For reasoning-rule changes, choose a few scenarios across different domains and
claim types, including a sound argument that needs no repair. Review actual
answers: bounded claim, appropriate evidence, justified next decision and
first-reader explanation. Keyword presence is not a pass criterion.

Record input/source version, actual answer, expected versus observed behavior,
reviewer and limitation. Label author self-review separately from an independent
evaluation; mark unexecuted cases `NOT RUN`. Compare the same inputs when claiming
an improvement. No extra model call or evaluation gate for ordinary research.

Historical shared-update discussions motivate R03-R06 and R14; they are examples,
not defaults for other domains. R19-R21 exercise formal reasoning, statistical
proxies and systems decisions. No fixture changes historical scientific results
or establishes generalization without actual behavior evidence.

R22-R29 add constructive explanation and review-mode cases. Include other domains
and a sound argument needing no repair when sampling them. A dated
[author self-review](../archive/process_records/constructive_reasoning_20261108_cn.md)
preserves actual answers and unrun evaluation limits; it is not an independent
old/new model comparison.

R30-R32 and their brief/facts-only variants have a separate
[supplement review](../archive/process_records/mechanism_bridge_20261108_cn.md).
Its recorded answers and author review do not constitute new model experiments.

R33-R34 and the sound-argument control R19 have a dated
[question-anchor author self-review](../archive/process_records/question_anchor_20261109_cn.md).
It records actual review answers, not an independent model evaluation or a
measured improvement over the previous rules.

R35-R38, plus unchanged logical controls, use the
[multi-turn continuity review](../archive/process_records/multi_turn_continuity_20261109_cn.md).
Review the complete turn sequence, not an isolated fluent answer. Preservation
checks and actual response review have separate scopes; neither establishes a
measured old/new improvement without a matched comparison.
