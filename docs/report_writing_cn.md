# 可独立阅读的科研文字规范

[English](report_writing.md)

目标是让读者首次阅读就能理解问题、推理、证据和边界。这些规则用于报告与解释，
不增加审批环节，也不改变科学判断的归属。

## 文字

- 优先使用短句、明确的主语和具体动词。把观察、解释、后果写清楚；一句话装不下
  它们之间的关系时就拆开。知道行动者时优先主动表达。
- 同一个对象使用同一个术语。必要术语和符号在首次影响理解时解释，不为修辞更换叫法。
- 尽早给出主要回答。一段展开一个要点，来源链接用于核查，正文仍需把意思讲清楚。
- 保留假设、量词、不确定性和适用范围。简化语言不能把局部结果变成普遍结论，
  也不能把假设写成结果、把数学关系写成因果发现。
- 中文保持自然，英文清楚直接。不把英文词数限制套到中文，不强行限制数学术语，
  未经专门检查不声称符合 ASD-STE100 全部标准。

## 先讲对象和操作，再给术语

任何必要术语首次出现时，先在正文交代：**指什么对象、怎样得到、怎样使用、
用于回答什么问题**。只给英文翻译，或用另一个抽象词解释它，都不够。
术语表辅助查找，不能替代正文中的解释。

分别说明构造方式、选择规则和学习状态。例如，汇总领域原始平均梯度构造的是
**共同更新**；在拟合数据上选一类更新、评价时处处使用它，是**固定选择**；
评价期间候选更新都不再变化，才是**固定候选库**。选择规则不是训练好的专家。
参数增量、它引起的激活位移、已学得权重的专家、仍在训练的共享模块必须分别定义。
具体操作回到各自 Protocol 和实现核对，不把其他实验的步长或接口搬过来。

## 每个比较先回答为什么做

正文在既有结构内依次讲清：

1. 要解决哪个具体疑问，它与根本问题有什么关系。
2. 原来的判断或候选假设，以及可信的竞争解释。
3. 改变什么、保持什么、比较什么。
4. 每个对照排除了什么解释，又排除不了什么。
5. 哪种结果会改变判断，包括不支持与证据不足的分支。
6. 实际结果支持什么、不能支持什么，以及据此作出的决定或明确标注的 AI 建议。

“进一步分析”“验证有效性”不能代替目的。恒等式不需要编造实验对手。
Summary 五部分和 Anchor 八节保持原职责；以上要求不新增审批表单。

## 公式含义与证据范围

公式附近说明符号所指对象、维度或单位、随机量、期望或平均范围、必要假设和用途。
写清是经验训练损失、留出数据损失还是总体风险；是总风险还是扣除不可约随机性后的
超额风险；是平方损失还是半平方损失；是精确关系、局部近似还是推测。
同名符号在不同模型中含义不同时，给出局部对应，或在当前说明中改名；冻结证据不改。
组平均梯度差异的方差不能直接当成均值估计的噪声协方差。

“噪声”要指出随机对象：给定可见前文后真实目标的条件变化、有限样本均值的估计误差，
或指定模型状态下的小批次梯度波动。“消噪声”必须交代操作和条件，不能暗指删去真实
组间差异或纠正错误标签。

分开写模型内推导、教学算例、语言模型实测、解释及未完成工作。固定模型上的一次更新
选择不是专家持续训练；赢使用率匹配随机对照不是赢强固定基线；区间跨零不证明完全
无效；实现失败或未运行不是架构负结果。保留数值、不确定性、版本和证据身份。
不将原始数据、日志、执行收据和冻结协议改写成新历史；当前报告解释历史适用范围。
个人焦虑和对导师的评价不写进科研报告。

每个实质章节开头说明解决什么问题，结尾说明改变哪个判断、留下什么不确定性。
删去无助于理解的重复；这些是含义要求，不强制反复使用同一组标签，也不要求加长正文。

## 内容与深度

### 目的、模型、假设、结论、分析

新写或修订的实验总结、多段式科研分析，按以下顺序叙述：

1. **目的：** 哪个未知值得研究，它与主问题有什么关系，回答它会改变什么认识。
2. **模型：** 定义实际系统、数据与任务、可训练与冻结对象、更新或干预、测量量。
   先说明必要数学关系与前提，再使用公式；区分实际实现和候选解释模型，标明精确、近似和尚未检验的关系。
   不为填满栏目编造模型。
3. **假设：** 写出可证伪的预期、最强可信竞争解释，以及能够区分二者的比较。
   保持原问题的对象、条件和时间范围；看到结果后提出的解释明确标为事后解释。
4. **结论：** 直接回答目的，用最少的决定性数值交代证据和范围。
   说明支持、削弱和尚未解决的判断；缺失的研究者判断保持 Unknown，文字整理不授予科学批准。
5. **分析：** 解释证据为什么支持上述结论。分开观察与解释，说明基线、改变与保持不变的量、
   实际步骤、指标与单位、汇总方式、不确定性、对照和剩余竞争解释。把推导与测量对应起来，
   分别报告重要残差、近似误差和数值误差。恒等式的实现核验不是机制证据。

结论放在详细分析之前，让读者先知道证据支持什么回答。这是阅读顺序，不是科研发生顺序，
也不允许在读证据之前先选结论。完整 Summary 使用
[英文模板](../templates/research_process/experiment_summary_template.md)及
[中文配套模板](../templates/research_process/experiment_summary_template_cn.md)。

日常回复也按这个逻辑组织，深度与当前问题相称。短答给出答案、关键依据和边界；
复杂问题保留理解所需的模型、推导和证据，不把每次回复扩成完整报告。

五部分用于完整 Summary 和明确请求的多段分析；短答不强制标题，也不新增文件或实验。已有推导直接复用；
纯理论问题用证明或反例检验，观察性工作不编造机制。组会先放主讲，再放细节与问答；
长报告先给简短的章节阅读顺序。

章节随研究类型调整。证明、观察、干预、工程比较需要不同证据，不为填模板编造实验或模型。
Anchor 保持八节契约，Summary 采用以上五部分顺序，Detailed 保持完整证据台账结构。
本次格式更新不批量改写历史记录或冻结 Protocol；按请求修订时保留数值、证据身份和结论边界。
完整报告采用已整合到
[最终报告技能](../.agents/skills/research-final-report/SKILL.md)的导师 research-exploration 方法：
把前提、模型、计算、检验和认识更新讲给具备基本数学与机器学习知识、但没读过本对话的读者。

## 结果分析与科学结论

**结果分析**解释测量、比较、不确定性、有效性与竞争解释。
**科学结论**回答最初的目的，说明这些证据怎样改变了对问题的理解。
结论只引用支撑认识更新所必需的证据，不能用数值列表或通过/失败标签代替回答。
详细分析留在 Detailed，Summary 只保留理解结论必需的支撑。

如果证据尚未改变科学判断，就说明哪个问题仍未解决；不为显得深刻而编造机制或扩大问题。
缺失的研究者判断仍为 Unknown，AI 的解释和下一步建议明确标注。

## 完整的 Markdown 交付

研究交付使用 Markdown/文字，不再生成或要求网页、交互查看器或视频。
静态图可补充文字，但不打开图片、不点击链接、不展开隐藏内容，也应能理解问题、关键发现、推理与边界。

- **阅读顺序：** 开头尽早说明问题、有边界的回答和证据状态；再按理解依赖解释对象、
  推理或比较、关键证据。补充推导和核查细节放在后面的明确标题下。长文可提供简短阅读顺序，
  写明章节或文件名；短答不用目录，不强制统一节数。
- **公式：** 先说明计算什么、为什么需要，再给公式；首次使用时定义符号、类型或单位与条件。
  用文字解释运算及其含义，区分精确关系、近似和假设。沿用[数学格式](markdown_math.md)，
  即使读者只能看到 TeX 源码，也能通过文字理解这一步的意思。
- **数字与比较：** 写清比较对象、基线、指标与单位、样本或聚合方式、决定性数值，以及
  不确定性或其缺失。便于比较时用紧凑表格，并用一句话解释结论；宽表不如短列表清楚时就改用列表。
- **图件：** 正文写清画了什么、比较条件、可见结果和限制，并保留数据来源链接。
  示意图只解释关系，不充当测量证据；不为满足格式编造图。
- **证据与导航：** 决定性陈述旁给出有含义的来源链接；正文保留评估该陈述所需的设置和解释。
  完整日志、配置和证据台账仍在各自原件。阅读入口同时给出文件职责和项目内路径，链接不能打开时
  也能找到文件。缺失来源和未知决定明确写出。

以上是内容要求，不是新增的强制栏目。相同条件与边界共用一次解释，不在每层重复整段结果。
便携 Markdown 包是派生阅读副本，修改仍回到原件；外部发送继续遵守请求范围。

## 检查文字本身

按顺序阅读交付的 Markdown，假设图、链接目标和富文本渲染均不可用。
检查读者能否说清问题、论证或比较为何能回答它、关键发现和未决事项；核对符号、条件、证据链接及来源一致性。
没有独立读者时称为自审。路径与源码检查不证明科学正确性，也不证明读者理解效果已经改善。
同时检查读者能否仅凭正文说明：研究对象、实际步骤、这样做的理由、对照为何有意义、
结果改变的判断，以及仍未回答的问题。不能访问的来源明确列出。

这吸收了 [Karpathy 帖子](https://x.com/karpathy/status/2105819303471976479)的简明表达建议，
并在本项目选择纯文字交付，没有另立一套报告模板。[STE 官方说明](https://asd-ste100.org/STE_faq.html)也支持把短句、明确术语、
主动表达应用到其他写作中。帖子所说的“80%”不是正式合规等级。
