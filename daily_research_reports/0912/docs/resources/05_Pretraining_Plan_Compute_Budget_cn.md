# 05｜预训练方案与四卡H100预算

**建议：32小时内先完成约3.13亿参数稠密模型的一条自然训练轨迹和可归因的SAE观察，不把15—20B词元、蒸馏、正则优势、普通MoE比较同时设为必交项。最终训练上限必须由真实四卡吞吐测量决定。**

## 1. 模型选择：回答“最新”与“本轮最合适”的区别

| Qwen3-0.6B基础模型架构 | 官方28层、16个查询头、8个键值头；主干接口已有明确代码 | 缩成10层、随机初始化，作为本轮推荐 |

**明确取舍：本包交付的是Qwen3风格的轻量研究实现，不是声称Qwen3是当前最新模型，也不是冒称复刻Qwen3.5。** 如果你把“必须用Qwen3.5”设为硬约束，就改用官方文本类、以完整的4层周期缩层，并重新做梯度/吞吐资格检查；不要在原有结果中途混换架构。该选项不列为本包已验证代码。

## 2. 推荐模型的精确配置

| 项目 | 数值 | 理由 |
|---|---:|---|
| 词表 | 151936 | 沿用Qwen3分词器的ID空间，便于相同词表的教师对齐 |
| 隐藏宽度d | 1024 | 保持近期分析接口，避免同时改变宽度与字典输入 |
| 解码层数 | 10 | 从28层缩到约三亿参数；这属于新随机模型，不是删预训练权重 |
| 前馈中间宽度 | 3072 | 采用门控前馈结构，不另加新激活机制 |
| 查询头/键值头 | 16 / 8 | 分组查询注意力；多个查询头共享键值 |
| 每头维数 | 128 | **不是1024/16=64**；官方Qwen3配置的投影宽度必须单独保留 |
| 查询总宽度 | 2048 | 16×128，与残差宽度1024不同 |
| 位置编码基数 | 1,000,000 | 旋转位置编码，单轮上下文固定2048 |
| 归一化 | 均方根归一化，epsilon=10⁻⁶ | 子层前归一化；查询/键分别按头归一化 |
| 输入/输出词嵌入 | 权重共享 | 词表很大，共享显著减少参数 |
| SAE宽度/最多激活数 | 8192 / 32 | 8倍过完备起点，不复现旧30000宽字典；先控制成本 |
| SAE位置 | 最后块残差经过最终归一化之后 | 正好是输出词表映射的输入 |

本包通过构造同形状模型并精确计数得到：主干312,892,928；SAE16,786,432；合计329,679,360个参数。输入共享嵌入约155.6M，占主干很大比例，因此“总参数313M”不等于313M都用于层内计算。SAE仅作为观察器时不增加主干预测容量。[本地参数计数；`scripts/inspect_parameter_budget.py`]

初始化全部随机，普通线性层/嵌入标准差0.02；归一化权重为1；不导入任何模型层权重。分词器不是神经网络权重，但它来自已训练模型系列，应如实登记为已有分词方案。

## 3. 训练数据：不重新下载一个完整大语料库

**优先使用你已有、来源明确、可快速读取的预训练文本。** 如果现有DCLM等缓存满足清洗与许可要求，先用它，不为这轮额外增加下载流程。现有路径在此无法核实，由Agent列出实际可读文件、字节数与哈希。

没有合适缓存时，备选是公开的FineWeb-Edu中的有限英文分片；它是教育质量筛选的网页文本，不是你已经使用过的语义真值集。[D1] 选英文语料就必须使用英文主探针，不能主要训练英文却用中文题目失败来推断没有语义。

建议首次锁定一个2B—4B词元的顺序前缀；15B—20B只作为后续扩展。分片清单固定后，按同一顺序扩展，不在看见模型表现后换成更容易的语料。

### 数据操作的固定顺序

1. 按原始整条文本进行基本清洗、空文本过滤和规范空白；先去精确重复，再按规范文本哈希分训练/验证/测试。不能在切成词元块后才随机划分。
2. 从模型训练语料中排除专门设计的探针文本、答案及同源改写；精确哈希只能去完全相同文本，近重复需要已有清洗工具补查，不能宣称本包实现了完整去污染。
3. 使用本地Qwen3分词器，不套聊天模板，不使用监督微调的仅答案损失掩码；本轮是文本下一词元预训练。
4. 文档末尾插入分词器真实EOS。不要把指令模型的EOS常数直接搬进基础模型的数据配置。
5. 用小端32位无符号整数储存词元ID。151936个词元的词表不能用16位整数完整表示。
6. 打包到2048上下文。首版允许跨EOS看到前一文档，所有分支一致；若改为文档隔离注意力，必须同时修改注意力掩码与跨文档预测损失，并重新比较吞吐。
7. 验证集与测试集文件不得进入SAE拟合、分组拟合、教师缓存选例和超参数选择。模型验证损失与语义确认集各有独立用途。

`data/prepare_tokens.py`已实现本地JSONL、整文档哈希划分、精确重复过滤、EOS、uint32分片和清单；读取在线语料、近重复清理、流式分词并行化与全量训练加载器由Agent补接。

## 4. 词元预算与训练时间：先算需要多快

令Q为四卡合计每秒完成的**有效下一词元预测数量**。T小时可处理的词元为D=3600TQ。吞吐必须包括主干、SAE、反向传播、优化器、梯度同步；真实平均吞吐还包括数据读取、保存和验证。

| 四卡有效吞吐情景 | 2B需要 | 4B需要 | 15B需要 | 20B需要 |
|---:|---:|---:|---:|---:|
| 80,000 /秒 | 6.94小时 | 13.89小时 | 52.08小时 | 69.44小时 |
| 150,000 /秒 | 3.70小时 | 7.41小时 | 27.78小时 | 37.04小时 |
| 250,000 /秒 | 2.22小时 | 4.44小时 | 16.67小时 | 22.22小时 |
| 350,000 /秒 | 1.59小时 | 3.17小时 | 11.90小时 | 15.87小时 |

以上只按D/Q计算，不承诺你的实现能达到任何一行。

20B在24小时内完成需要约231,481有效词元/秒；在16小时内完成需要347,222/秒。15B对应约173,611/秒和260,417/秒。32小时还必须包含资格检查、读法对照和汇报准备，不能把32小时全部乘成训练容量。

### 浮点运算只作合理性检查

简化训练成本约为6PD。P=312.893M、D=20B时约3.75×10¹⁹次运算。长序列注意力还带来额外项，按10层、序列2048、查询宽度2048估计，训练的注意力矩阵运算约增加0.50×10⁹次/词元；重计算、SAE和实现低效另外计。

H100官方高峰值表里存在采用稀疏性的数值，不能直接当稠密训练实效。即便用H100 SXM的约989TFLOPS稠密BF16峰值，乘以四卡再假设利用率，也只是理论预算；PCIe型号、互联、词表投影和实际内核可能让结果差很多。[H1]

## 5. 资格微基准如何测

先由Agent确认：四张卡实际型号、显存、互联、驱动、PyTorch/CUDA版本、剩余磁盘、作业最长时限、是否可恢复。不要假设“reserve”意味着不失败或没有排队。

运行`torchrun --standalone --nproc_per_node=4 -m scripts.benchmark_step --mode observer`。脚本默认每卡2×2048词元、SAE每8个位置取1个、预热10步、计时30步；它只测系统，不产生科学训练证据。

分别测none与observer，并在同一个已保存主干初态上做100—200步真实数据资格跑。SAE采样使用独立随机数流，正式训练不能永远选固定序号余数；默认每个窗口随机选择约1/8有效位置，分布覆盖后见06。

记录95分位步时、平均有效词元/秒、峰值显存、SAE时间比例、存档暂停时间。用真实资格跑的有效吞吐打八折估算可用预算；这个八折是计划余量，不是模型性能指标。若观察器导致超过20%的时间损耗，优先把采样从1/8改到1/16，并登记测量延迟；不先缩词表或换主干。

30步随机微基准不能替代多节点/长时间稳定性检查；本包尚未在H100上执行该脚本。

## 6. 优化器与训练超参数：一套可运行起点，不是最优配方

| 项目 | 首版建议 |
|---|---|
| 主干优化器 | AdamW，学习率3×10⁻⁴，β=(0.9,0.95)，epsilon=10⁻⁸ |
| 权重衰减 | 主干矩阵0.1；偏置与归一化0；SAE单独参数组、衰减0 |
| SAE优化器/参数组 | Adam，或AdamW且衰减0；学习率10⁻³，β=(0.9,0.999) |
| 精度 | BF16自动混合精度；归一化与损失累积用FP32；不先上FP8 |
| 全局批量 | 约262144输入词元/更新；统计有效预测词元作主要横轴 |
| 梯度累积示例 | 4卡×每卡2×2048×16次累积；真实分母按有效掩码计算 |
| 梯度裁剪 | 主干与SAE分别记录范数；阈值1.0作保守起点 |
| 学习率日程 | 按已处理词元计：前20M暖身，之后先保持固定平台；需要长跑衰减时在各臂共同约定的词元点开始 |

不能给短跑用2B余弦终点、长跑用20B余弦终点，然后把早期差异全部说成训练数据量作用。动态形成研究需要登记学习率曲线，因为学习率变化本身会改变演化速度。

观察器损失的权重1只影响SAE参数，不影响主干；这个数不可与允许SAE反馈时的权重直接比较。辅助反馈分支的权重见06，不能默认同样设成1。

## 7. 内存、存储与作业恢复

四卡数据并行，每卡一份313M主干通常比从一开始做模型并行简单。模型参数本身不是唯一显存来源：词表投影、中间激活、优化器和重计算都需要测。示例2×2048×151936的完整BF16 logits就约1.24GB，还不含梯度或FP32损失临时量。

本包按128个预测位置分块计算词表交叉熵，并对分块损失重计算以避免保留所有大词表激活；这是正确性优先的参考路径，不承诺比融合交叉熵快。Agent可接入已有融合实现，但必须先通过损失与梯度一致性检查。

20B uint32词元约80GB，4B约16GB，不含文本、清洗中间件和多个分片副本。313M模型的BF16参数约0.63GB；若保存FP32参数与Adam两份FP32矩估计，三者合计约3.75GB，另加SAE、调度器、随机状态等。具体是否另存主权重取决于训练框架，按真实文件大小预算。

早期检查点按0、1M、4M、16M、64M、256M、512M、1B、2B、4B保存，达到哪个存哪个；超过4B再按固定1B间隔保存。它们是目标附近的实际更新边界，不能把实际处理量伪装成刚好目标值。

模型权重与观察器必须成对保存；完整恢复还包括优化器、学习率调度、词元计数、数据游标、所有随机数状态、采样种子、分词器哈希、分组版本、配置与代码版本。每隔30—60分钟另存最近可恢复检查点。`save_checkpoint()`本身仅保存模型，不能冒充完整训练恢复。

## 8. 蒸馏：什么能快，什么不一定快

知识蒸馏（Knowledge Distillation）是让学生模仿教师的输出等信息。它可能减少达到某种行为所需的学生更新，但教师推理也耗时，所以不自动降低总墙钟时间。

**本轮默认不开四卡上同时跑30B教师的在线蒸馏。** 最小备选是你已经能稳定运行、词表相同的Qwen3-0.6B基础教师；先给有限训练前缀缓存输出的最大16项概率与剩余质量。教师应接收到与学生相同的可见前缀，不能给教师看未来答案、再把完整答案隐藏状态当当前因果目标。

完整词表BF16概率每个位置约304KB，20B位置约6.08PB，不现实。仅16项的32位ID、16位概率与尾部质量也约98字节/位置，20B仍约1.96TB。先缓存一小部分位置，例如10M个有效位置约0.98GB，另加前缀定位与清单；教师缓存生成时间算入预算。

目标定义为：

$$L=L_{\mathrm{next\ token}}+\beta T^2\mathrm{KL}(p_T^{\mathrm{coarse}}\Vert p_S^{\mathrm{coarse}}).$$

“coarse”指最大16项各自保留，再把其余词表合成一个尾部类别。它不是完整词表KL，不能把教师最大项重新归一化后假装忽略的概率为零。温度T必须在生成缓存时确定，之后不能用同一缓存随意改温度。`utils/distillation.py`实现该损失的参考计算。

蒸馏触发条件：自然主轨迹已健康运行，但指定关系仍弱；已知教师在同一探针上确实有可检测信号；缓存与匹配两条短分支能在剩余预算内完成。不满足就不蒸馏。若进入此分支，必须从同一学生检查点，使用相同数据，比较有/无教师；不能只展示蒸馏分支。

这得到的是“教师监督条件下的形成数据点”，不等于自然形成的复制。也不能同时再加入SAE语义反馈，否则教师和SAE作用无法拆开。[M，13:24—13:46]

## 10. 本轮必须回答与后续再回答

必须：这是从随机开始的真实学习轨迹吗；SAE是否具备读取资格；观测变化主要在哪些计算环节发生；指定语义与格式解释能否区分；下一次应该改哪一环。

可以后续：20B完整预算与更高能力；多主模型种子确认；SAE特有正则相比一般正则的净收益；专家架构、普通MoE相对缺陷与功能干预；大规模数据效率或遗忘收益。它们没有被否定，只是不属于单轮32小时的共同成功条件。
