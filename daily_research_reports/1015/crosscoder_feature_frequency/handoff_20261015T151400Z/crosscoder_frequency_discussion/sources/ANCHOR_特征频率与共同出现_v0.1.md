# Anchor：特征频率与共同出现关系能否提供分组依据

状态：讨论初稿 v0.1，2026-10-15。当前只授权资产核对和 protocol 编写；正式分析、重新编码大批数据和训练须等待确认。

## 1. 总目标与本轮问题

长期目标：在参数和计算预算受限时，让不同专家形成有用的分工，提高参数利用效率。是否改善学习、是否提高容量，最终仍需任务实验验证。

本轮问题：已有 CrossCoder 的特征是否存在可重复观察到的共同出现关系？按照这种关系形成的特征组，内部出现频率是否比合适的随机对照更接近？这些组能否对应到不同的输入位置？

本轮先分析结构，不回答“共同出现就应该共同学习”，也不声称容量提高。我们用结构结果决定后续值得比较哪些分配方案。

用户的 common 设想：router 可以侧重输入之间的区别；被选中的专家仍处理完整输入，包括共同成分。不是让每个专家处理全部 token，也不是删除模型中的 common 分量。它不同于单独设置 common expert，后者不在本轮实现。

## 2. 直觉、假设与竞争解释

直觉：若某些特征在很多独立文本中反复一起出现，它们可能共同描述一类输入。若组内频率也接近，按输入组织特征与按频率组织特征可能给出一致的候选分组。

H1（结构假设）：在考虑各特征自身出现频率和稀疏激活约束后，仍存在可在留出文本复现的共同出现关系，并可形成稳定的特征组。

H2（频率假设）：不使用频率接近程度来构建这些组时，组内特征的频率差异仍小于合适的随机对照。

H1 与 H2 分开裁定。发现共同出现组，不代表 H2 成立；H2 成立，也不代表学习获益。

竞争解释：高频特征本来就容易与所有特征一起出现；TopK 竞争或 BatchTopK 推理方式可能产生统计关系；少数文档、重复文本或文本来源可能主导关系；小样本的低频特征可能产生极大的比值；建图指标与候选筛选本身可能偏好相似频率。

需要检查跨来源是否复现，但来源相关不自动意味着无价值。应分别报告“来源内也存在”与“主要由来源混合产生”，不要未经定义就把领域差异全部消掉。

## 3. 固定对象与术语

- 输入单位：一个有效 token 位置及其可见上下文。排除 padding，明确特殊 token 策略；保存文档、上下文和位置 ID。
- feature：固定 CrossCoder 的一个潜在坐标 i，激活值记为 z_i(x)。不预设它对应独立知识或唯一语义。
- 激活事件：a_i(x)=1[z_i(x)>τ_i]。阈值规则须从当前推理代码和归一化方式确认。若稀疏激活精确非负且零具有明确定义，可提出 τ=0 作为主方案；不能未经检查硬套。
- 出现频率：p_i=Σ_x a_i(x)/N。它不同于平均激活幅度、解码范数和目标 token 频率。多个特征可以同时出现，Σ_i p_i 不必为 1。
- 解码向量 d_i,ℓ：该坐标在模型层 ℓ 的重建方向。范数不是该输入是否激活。共享潜变量 z 不能被当作每层独立观测的激活。
- 共同出现：在同一个 token 位置同时激活。跨 token 窗口共现是另一个问题，暂不混用。
- 特征组：根据共同出现关系得到的候选集合，可重叠与否由 protocol 说明。它不是专家，不是已证实的组合语义或因果层级。
- common：相对于已得到的多个组，经常在这些组对应输入中共同出现的成员；先测量，不能直接把全局 Top10 当作全部 common。

## 5. 分析方法的初版实现建议

### 分析一：频率分布是否稳定

按文档划分发现集与验证集，禁止同一文档片段跨集合；检查重复和近重复。使用固定编码器、推理设置及激活阈值，从缓存累积激活次数、有效位置数、覆盖文档数；同时保留激活幅度作为单独诊断。

先画频率排名曲线和非零频率分布，报告零命中特征比例。零命中只表示当前窗口未见，不能认定永久死亡。不要看到长尾就宣布存在天然层级；人为分位分档只能作为描述工具。

比较两份数据中的频率排序与估计范围；不把 token 当独立样本，按文档/独立上下文重采样。最小出现次数、最少文档数以及样本量由 pilot 计数或已有统计决定，并写明选择依据。支持不足的特征列为未裁定，不能当作无关系。

### 分析二：定义超出高频背景的共同出现关系

先保存原始计数 n_i、n_j、n_ij、N 和覆盖文档数，再派生指标：

p_ij=n_ij/N；P(j|i)=p_ij/p_i；提升比 lift_ij=p_ij/(p_i p_j)。

lift 说明相对独立频率基线多出现多少，但对罕见事件敏感，不能单独按最大 lift 选边。P(j|i) 大也不足以说明特殊关系，因为 j 可能本来就很常见。

protocol 需选一个主建图量和一个必要的敏感性量，并说明支持度筛选、统计不确定性、多重比较和随机基线。可提出二元相关系数 phi=(p_ij-p_i p_j)/sqrt[p_i(1-p_i)p_j(1-p_j)] 作为候选主量，但必须说明其受边际频率约束，p=0 或 1 不适用。不要把指标选择伪装成已确定的方法。

优先在稀疏激活索引上分块累积共同出现计数，不构造 N×F×F 张量。说明时间和内存复杂度；若需要缩小候选集，依据计数可靠性和资源上限，而不是为了得到预期结果挑特征。候选集之外不能外推无关系。

随机对照不能只打乱 feature ID。独立打乱每列保留频率但破坏每个位置的激活数量，可作为弱基线。对于固定/竞争性稀疏编码，优先讨论保留每个特征命中总数及每个位置激活数的二元矩阵交换对照，并说明适用限制、混合检查及计算成本。数据来源分层对照可用于定位来源效应。protocol 不必堆所有方法，但必须选出能裁定主假设的最低充分组合。

### 分析三：共同出现组与频率是否一致

在发现集上按关系建组，不把频率距离放进分组目标。protocol 选择一种主分组方法及分辨率规则，说明有边但无清楚群组时如何报告，不强迫得到漂亮聚类。

冻结候选组后，验证集检查组内共同出现关系与稳定性。再测组内 log 频率离散度：例如对有足够支持的成员使用 log10(p_i) 的标准差；每组、每个 feature 等权的结果需分开说明。零命中不任意加常数后当正常频率处理，应标为不可估计或区间。

比较同等组大小、同等候选池的随机分组；另用组平均 log 频率近似匹配的对照，防止高频组和低频组的自然离散度差异混入比较，但不要逐成员精确匹配频率而把待检验差异消掉。并检查图算法和建图量自身是否偏好相近频率。必要时对保留边际的随机数据执行同样的候选筛选、建图和分组流程，以免把建图机制的偏差当成频率规律。若简单随机组和结构保留对照结论不同，应如实报告。

### 分析四：这些组对应哪些输入

保存组内代表位置的完整可见上下文、激活成员和数值：同时提供随机样本与高激活样本，不只展示最漂亮的例子。

如果要从特征组映射到输入，先定义组得分及命中规则，再在验证集报告唯一归属、多组命中和未命中的比例。所有阈值在发现集确定，不能按验证集效果调节。

标记跨组共有成员和更具区分性的成员。可以比较“全部成员”与“仅用区分性成员”的输入分组一致性，但不从真实模型表征中删除共同分量。若多组重叠很强，这本身是普通 top-1 路由难以按特征独立分配的约束，不要强制给每个位置唯一标签后隐藏冲突。

## 6. 预期图和数据交付

1. 频率排名图：横轴排名，纵轴出现频率；发现/验证集分线，注明对数轴、零命中和有效位置数。
2. 频率稳定图：横轴发现集频率，纵轴验证集频率，标明支持不足部分；不能只给总体相关系数。
3. 共同出现关系图或矩阵：边/颜色含义写清；频率用节点大小或附表表示，避免把频率同时用于构图。选择子图要有透明规则，完整计数另存。
4. 组内频率差异图：横轴真实组和匹配对照，纵轴预定义离散度；给逐组结果、组大小和重采样区间。
5. 输入审阅表：组 ID、随机/高激活、上下文、激活成员、其他组命中情况。文本仅保存在授权项目中。

## 7. 结果怎样更新认知

- H1 支持且 H2 支持：在当前编码与数据范围内，共同出现关系与同频分组相容；可构造后续学习对照，不等于已证明学习有益。
- H1 支持、H2 不支持且估计足够精确：特征组织包含明显混频；按共同出现与按频率分组可能给出不同建议，后续应比较这两类策略。
- H1 未获支持：先区分统计能力不足、编码/缓存问题和确实缺少可复现关系；不能一律宣布结构不存在。
- 有组但输入大量多组命中：特征分组到 token 路由的映射存在限制，需要调整路由假设，不能直接一组一专家。

“有关系”“频率相近”“能分输入”“学习有益”是四个不同结论。本轮最多讨论前三个，第四个待后续实验。
