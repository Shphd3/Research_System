# E002: Correlation-Aware Feature-Zipf Routing

## Decision Question

In correlated Feature-Zipf synthetic representations, does explicit feature-correlation routing recover tail feature routing and function-level mechanism better than current routing baselines?

## Mainline Anchor

The project studies whether MoE specialization can align with sparse, Zipfian, compositional feature structure in representation space.

E001 showed that Hierarchical MoE has a weak function-level recovery signal, but it did not beat Flat middle spectral routing at sparse feature division.

E002 tests the next hypothesis: the missing routing bias may be feature correlation, not hierarchy alone.

## Hypothesis

If sparse features have common → group → unique correlation structure, then a router that explicitly uses feature-feature correlation should improve tail feature routing and function-level recovery over a matched feature-only hierarchical router.

## Setup

Use the existing Feature-Zipf synthetic setup.

Recommended default:

```text
hidden_dim = 1024
common features = 16
coarse groups = 10
group features per coarse = 6
unique features per coarse = 10
train = 20000
valid = 5000
test = 5000
seeds = [0,1,2]
```

Sample types:

```text
common-only = 0.40
group-only = 0.35
group+unique = 0.25
```

Add correlation strength:

```text
rho = 0.8
```

With probability `rho`, group and unique features are sampled from the same coarse relation block. With probability `1-rho`, relation noise is injected by sampling a mismatched group or unique feature.

## Models

Run exactly four model arms:

1. `flat_middle_spectral_common`
2. `hier_conditional_input`
3. `hier_feature_only_z_gate`
4. `hier_correlation_aware_z_gate`

Primary comparison:

```text
hier_correlation_aware_z_gate vs hier_feature_only_z_gate
```

Secondary comparison:

```text
hier_correlation_aware_z_gate vs flat_middle_spectral_common
hier_correlation_aware_z_gate vs hier_conditional_input
```

## Correlation-Aware Router

Let `z` be the true latent sparse feature activation vector in the synthetic data.

Estimate feature relation matrix `C` from training activations:

```text
C_ab = max(PMI(z_a, z_b), 0)
```

Remove the diagonal, keep top-16 neighbors per feature, and row-normalize.

Compute:

```text
r = C z
```

Router input:

```text
[z ; r ; z * r]
```

where `*` is elementwise product.

## Built-In Control

Run the correlation-aware router with:

```text
C_correct
C_shuffled
```

If correct-C and shuffled-C perform similarly, do not claim relation-aware routing.

## Metrics

Primary:

- tail Leaf NMI ↑
- Function Cos ↑
- Atom Diversity ↑
- Top Atom Overlap ↓
- group+unique ablation loss delta ↑

Control:

- correct-C vs shuffled-C gap

## Decision Rule

H2 is weakly supported only if:

1. correlation-aware router beats feature-only router on tail Leaf NMI in at least 2/3 seeds;
2. correlation-aware router beats feature-only router on Function Cos in at least 2/3 seeds;
3. mean tail Leaf NMI improves by at least +0.03;
4. mean Function Cos improves by at least +0.02;
5. test loss is not worse by more than 2%;
6. correct-C beats shuffled-C.

If the result fails these checks, stop architecture expansion and report the negative result.

## Claim Boundary

Can say:

- correlation-aware routing helps in this controlled synthetic setting, if metrics pass the decision rule;
- explicit feature relations may be a useful routing bias.

Cannot say:

- real language hidden states have this exact correlation structure;
- attention provides the true semantic relation;
- correlation-aware routing solves forgetting;
- Hierarchical MoE is generally better than Flat MoE.

## Expected Result File

Write final result to:

```text
results/R002_correlation_aware_feature_zipf.md
```
```
