# 执行结论

## 最终判断

**现在应当把主要实验载体从“从头预训练或改造预训练范式”转向“基于已训练基座的参数高效适配”，但不要把方向宽泛地改成“研究 Post-training”。**

下一阶段更准确的研究对象是：

> **在冻结或基本冻结的 Qwen3-0.6B 基座上，利用模型已有的语义判别能力为路由器提供粗粒度监督，使不同低秩适配专家仅通过各自接收样本的任务损失形成可验证的功能专门化；先验证真实标签上界，再验证模型产生的伪标签能否复现该方向。**

这不是放弃“根本创新”，而是把创新位置从高成本的预训练全流程，移动到一个可控、可归因、可重复的预训练后适配阶段。你的表征空间、语义可分性和 Router 研究经验都能直接迁移过来。

## 唯一需要解决的问题

> **一个已经具备语义判别能力的小型语言模型，能否用自身产生的语义信号训练 Router，使 LoRA 专家形成对相应语义类别具有选择性因果效用的专门化，而不只是让路由标签更纯或表征图更好看？**

这里的最终对象不是“表征是否更可分”，而是“专家是否形成了可验证的功能专门化”。表征可分性只是机制证据之一。

## 36 小时可以完成到什么程度

36 小时足以完成一个**决定路线是否继续的最小闭环**：

1. 确认 Qwen3-0.6B Base 或其 Post-trained 版本是否能稳定地产生粗粒度语义标签；
2. 在完全相同的 LoRA 专家树、参数量、活动计算量和数据顺序下，比较“任务损失训练”与“真实语义标签监督 Router”；
3. 只有真实标签组通过，才运行模型伪标签组；
4. 用错误专家强制路由、正确专家删除和专家交换，验证专家效用是否具有语义选择性；
5. 给出目标任务结果、一般能力守卫、表征证据与明确的不能声称边界。

36 小时不足以同时完成完整粗细两级动态生长、RL、多个公开大基准和论文级充分复现。若真实标签上界未通过，应立即停止，不再投入伪标签、去粗方向或 RL。

# 第二部分　Pre-training、Mid-training、Post-training 与 RL 的根本区别

## 2.1 先给最重要的判别规则

**训练阶段不能只根据“从哪个 checkpoint 开始”判断，也不能只看损失公式是否是交叉熵。真正的判别依据是：数据承载什么监督、训练要改变什么能力、评价契约是什么。**

例如：

- 从预训练模型出发，继续在原始领域文本上做下一词元预测，仍然属于持续预训练或 Mid-training；
- 从预训练模型出发，在“指令—回答”数据上只对回答词元计算损失，属于监督式 Post-training；
- 用偏好对做 DPO，属于 Post-training，但不是强化学习；
- 让模型采样回答、获得标量奖励，再用策略梯度更新，属于使用 RL 的 Post-training；
- 用语义标签训练 Router，同时让 LoRA 专家通过下游任务损失学习，属于预训练后参数高效适配，通常应归入 Post-training；若专家任务仍是大规模原始文本下一词元预测，则更准确地称为“Mid-training 与监督路由的混合适配”。

## 2.2 四类训练的对照

| 维度 | 预训练 Pre-training | 中期训练 Mid-training | 后训练 Post-training | 强化学习 RL |
|---|---|---|---|---|
| 核心目的 | 从大规模数据中形成通用语言建模能力、知识与基础表示 | 在预训练后段或预训练完成后，缩小通用语料与目标领域、长上下文、推理或指令分布之间的差距 | 把已有能力组织成可调用的任务行为、指令遵循、偏好、领域技能或安全行为 | 用标量奖励优化策略行为；它是优化方法，不是独立生命周期阶段 |
| 典型数据 | 海量原始或弱清洗文本、代码、多模态序列 | 更高质量、更专门、更接近目标分布的数据；可能是领域文本、推理数据、长上下文或指令化文本 | 指令—回答示范、任务标签、偏好对、教师生成数据、可验证问题与奖励、语义或路由标签 | 模型自己采样的轨迹/回答，加人类、奖励模型或规则验证器给出的奖励 |
| 数据行为 | 主要告诉模型“真实序列通常如何出现” | 重新加权模型应重点建模的数据分布 | 明确告诉模型“面对某类输入应该怎样回答或选择” | 不直接给唯一正确词元，而给整段行为的好坏信号 |
| 常用损失 | 自回归下一词元交叉熵、掩码建模或多模态预训练目标 | 通常仍是下一词元交叉熵，但数据分布和混合方式改变；也可带少量辅助目标 | 监督微调交叉熵、知识蒸馏、分类/对比损失、DPO 等偏好损失、路由监督损失 | PPO、GRPO、RLOO 等策略梯度目标，通常带 KL 约束 |
| 参数更新 | 通常全参数、长周期、大 token 预算 | 常为全参数或较大范围更新，预算小于主预训练但仍可能很大 | 可全参数，也可只训练 LoRA、Adapter、Router、奖励模型等少量参数 | 更新策略模型的全部或部分参数；还可能训练奖励模型/价值模型 |
| 输出模型 | Base model | 更适合目标分布的 Base/Intermediate model | Instruct、Chat、Reasoning、Domain-adapted 或工具使用模型 | 通常是 Post-trained policy |
| 主要风险 | 成本高、组件耦合强、归因困难 | 灾难性遗忘、数据混合和阶段时机敏感，算力仍较高 | 过拟合、能力遗忘、标签偏差、捷径学习 | 奖励投机、高方差、训练不稳定、采样成本高 |

## 2.3 损失函数的形式

### 预训练或持续预训练

对序列 \(x_{1:T}\)，典型下一词元损失为

\[
\mathcal L_{\mathrm{NTP}}
= -\mathbb E_{x\sim\mathcal D}
\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t}).
\]

Mid-training 往往不改变这个公式，而是改变 \(\mathcal D\)：提高数学、代码、领域文本、长上下文或指令化数据的权重。

### 监督式 Post-training

对指令 \(q\) 与目标回答 \(y\)，通常只在回答部分计算

\[
\mathcal L_{\mathrm{SFT}}
= -\mathbb E_{(q,y)\sim\mathcal D}
\sum_{t\in y}\log p_\theta(y_t\mid q,y_{<t}).
\]

它与下一词元预测在数学形式上相似，但训练数据包含了“输入—期望行为”的监督，因此研究对象不同。

### 偏好优化

对偏好回答 \(y^+\) 和非偏好回答 \(y^-\)，DPO 直接比较策略相对参考模型对两者的偏好：

\[
\mathcal L_{\mathrm{DPO}}
= -\mathbb E\log\sigma\!\left(
\beta\left[
\log\frac{\pi_\theta(y^+\mid q)}{\pi_{\mathrm{ref}}(y^+\mid q)}
-
\log\frac{\pi_\theta(y^-\mid q)}{\pi_{\mathrm{ref}}(y^-\mid q)}
\right]
\right).
\]

DPO 使用偏好数据，却不需要在线采样和策略梯度，因此不能简单等同于 RL。

### 强化学习式 Post-training

典型目标是

\[
\max_\theta\;
\mathbb E_{q\sim\mathcal D,\,y\sim\pi_\theta(\cdot\mid q)}[r(q,y)]
-\beta D_{\mathrm{KL}}(\pi_\theta\Vert\pi_{\mathrm{ref}}).
\]

模型必须生成轨迹，奖励函数评价结果，再把序列级奖励分配回各个决策。这正是 RL 比 SFT 或路由分类更昂贵、更不稳定的原因。

## 2.4 “四个阶段可以统一”究竟成立到什么程度

在很高层的数学抽象下，它们都在某个数据分布与监督信号下优化模型参数，因此可以写成统一的风险最小化或期望效用最大化问题。这种统一视角有助于研究“数据、目标、优化器和模型结构如何共同塑造表示”。

但它不能消除以下操作差异：

- 原始数据、示范、偏好与奖励携带的监督信息不同；
- 教师强制、离线偏好学习与在线采样的梯度估计不同；
- 需要的算力、稳定性技术和评价指标不同；
- 一个在 SFT 中有效的 Router，不自动在大规模预训练或 RL 中有效。

所以“大一统”可以是长期理论目标，却不应成为当前必须同时覆盖四种训练阶段的实验要求。

## 2.5 截至当前最稳固的 Post-training 共识

1. **先用直接监督建立行为，再考虑偏好或奖励。**监督微调通常负责建立任务格式和基础能力；偏好优化用于选择“哪种回答更好”；可验证奖励强化学习更适合数学、代码等结果可自动判定的任务。三者不是每个项目都必须全部使用。
2. **数据定义往往比优化算法更重要。**示范质量、难度分布、类别平衡、去重和污染控制会直接决定结果；不能只更换 DPO、PPO 或 GRPO 而忽略数据。
3. **目标能力与保留能力必须同时评估。**Post-training 应同时报告目标任务增量和一般能力回退，不能只看一个聚合平均分。
4. **参数高效适配是资源受限研究的标准工具。**LoRA 或 Mixture-of-LoRA 允许冻结基座，在较低显存下研究数据分配、路由和功能模块形成。
5. **RL 只在奖励对象已经清楚时进入。**若当前目标可以用真实语义标签、任务损失和专家反事实效用直接监督，优先使用监督学习；过早加入 RL 只会增加采样成本和归因困难。
6. **开放后训练流程强调开发集、未见集与去污染。**一套方法需要在开发集上做决策，在独立未见测试上裁定，并报告不起作用的方法和能力回退，而不是只展示最终最好配置。

# 第四部分　导师思路的推理逻辑链与审计

## 4.1 导师的完整逻辑链

### 第一步：接受一个有限正结果

无监督标签虽然没有提高下一词元预测效率，但它与真实标签的对齐高于原方法。这说明“模型产生某种内部分类信号”可能是可行的，不应因为最终任务尚未提升就立即否定。

### 第二步：重新定义可能的价值

导师把价值从单一的训练损失收敛速度扩展为：

- 学习时减少不同语义数据之间的参数干扰；
- 推理时只访问相关专家或相关 KV 子集；
- 后训练时把新知识写入更合适的层和专家。

### 第三步：提出机制

已有语义认知先完成粗分类，Router 再把不同语义样本送到不同专家；专家只通过收到样本的任务损失学习。这样，语义分类承担“分配”，任务损失承担“学习”。

### 第四步：提出层级生长

先按物理、数学、化学等粗类别分开；当某一粗类内部积累足够知识后，再分成更细子类。因此专家结构不是一次性固定，而是可能由粗到细生长。

### 第五步：解释为什么分类信号可能先出现

生成正确回答需要组合完成任务所需的多种特征；粗分类只需找到足够区分类别的证据。因此，模型可能先具备可用的语义分类能力，再具备高质量生成能力。

### 第六步：诊断现有失败

从头训练的两层或三层模型没有足够语义认知，却被要求同时发现标签和利用标签。这造成循环依赖：

\[
\text{没有语义能力}
\Rightarrow \text{标签不可靠}
\Rightarrow \text{路由不能形成专门化}
\Rightarrow \text{表征仍然混乱}.
\]

### 第七步：提出修复

使用已经预训练好的小型 Dense 模型作为语义起点，在其上加入 Router 与 Expert LoRA。最初允许真实粗标签或语义描述作为先验；等模型形成可靠路由后，再逐步减少外部监督，转向模型伪标签或自演化。

## 4.2 这条逻辑链中尚未得到证明的环节

### 未证明 1：分类一定比生成更容易

这只是任务依赖的直觉。某些类别需要深层推理才能区分，某些生成任务反而可由模板完成。因此必须直接测量标签的未见样本准确率和稳定性。

### 未证明 2：语义路由一定提高学习效率

即使路由标签很准，专家参数也可能学习相同函数，或由于每个专家见到的数据减少而更慢。必须在相同参数量、活动计算量和 token 预算下比较，并做专家删除实验。

### 未证明 3：LoRA 激活与标签对应就代表专家专门化

Router 可以按标签分发，但所有专家仍然学到近似相同的映射。路由纯度只是“谁接收了数据”，不能证明“谁学会了独特功能”。

### 未证明 4：专家表征彼此正交是正确目标

严格正交既非语义可分性的必要条件，也难以在特征数远大于维度时成立。更合理的目标是：在给定父类和任务条件下有正间隔，并且删除对应专家时只对匹配样本产生更大损失。

### 未证明 5：LoRA 路由会自动降低 KV cache 成本

普通 Expert LoRA 只改变网络参数路径，并不会自动把 KV cache 按语义分区。要得到十分之一 KV 访问量，需要额外设计语义索引、缓存分区和检索协议。这是独立的系统研究，不是当前实验可声称的收益。

## 4.3 当前最强竞争解释

即使使用预训练模型后获得了好结果，最强竞争解释仍是：

> **预训练模型原本就已把语义分开，新的 Router 只是读取已有类别；额外 LoRA 容量或数据分组改善了任务，而不是语义监督形成了新的功能专门化。**

因此，必须同时比较：

1. 原始基座表示与加入专家后的有效表示；
2. 同架构、无语义监督的 Router；
3. 打乱标签监督；
4. 专家删除、专家交换和强制错误路由；
5. 匹配类别与非匹配类别上的损失变化。

# 第五部分　是否应从 Pre-training 转向 Post-training

## 5.1 确定判断

**应当转。**

但要把表述改为：

> **从“修改大规模预训练范式”转向“在预训练基座上研究语义监督如何形成可控的专家化适配”。**

理由有三点：

1. **算力与归因匹配。**预训练中的组件高度耦合，单个 Router 改动需要长训练才能判断；冻结基座并只训练 Router/LoRA 后，可以在较短周期内做严格因果对照。
2. **与现有主线连续。**你当前研究的核心仍然是表征可分性、语义层级和专家专门化，只是把“从零形成”改成“利用已有语义能力重新组织适配”。
3. **有真实文献与基线可比较。**LoRA、MixLoRA、HMoRA、MoELoRA 和 SAMoRA 已形成清楚的实验范式，可以让你的工作被放进可比较的研究语境中。

## 5.2 不应怎样转

不应直接把问题改成：

- 怎样把通用模型做得更会聊天；
- 怎样复现 DPO/PPO；
- 怎样在所有 Post-training Benchmark 上刷分；
- 怎样立刻用 RL 学 Router。

这些问题会丢失你已有的表征与专家化主线。

## 5.3 你真正保留的创新对象

现有工作已经覆盖“多 LoRA 专家”“层级路由”“语义感知路由”。因此，以下表述本身不够新：

> 使用语义信息把样本路由到不同 LoRA 专家。

更有区分力的研究对象是：

1. **标签来源**：不是固定任务 ID，而是模型已有语义能力产生的、可更新的层级标签；
2. **形成过程**：从外部粗先验启动，逐渐转成模型自身标签并向细粒度生长；
3. **证据标准**：不以路由纯度或最终分数替代机制，而以选择性专家因果效用证明专门化；
4. **表征链条**：明确区分原始冻结表示、专家残差和有效表示，解释可分性究竟在哪里形成；
5. **失败边界**：标签入口、真实标签上界、伪标签传递和功能收益任何一关失败都停止。

# 第六部分　唯一问题的拆分与实验假设

## 6.1 核心问题

> 在冻结 Qwen3-0.6B 基座后，模型产生的粗粒度语义标签能否训练序列级 Router，使不同 LoRA 专家形成对相应语义类别具有选择性因果效用的专门化，同时保持或改善目标任务？

## 6.2 四个必要子问题

### 子问题 A：语义入口是否存在

Qwen3-0.6B-Base 与 Qwen3-0.6B Post-trained 模型，哪一个能够仅根据输入、在不读取答案的情况下稳定区分粗语义类别？

这一检查决定后续主张：

- Base 已能区分：预训练形成了可用语义入口；
- 只有 Post-trained 模型能区分：该入口依赖既有后训练；
- 两者都不能：当前任务或标签定义不适合作为自路由入口。

### 子问题 B：正确语义监督是否具有因果作用

在同一基座、同一专家树、同一任务数据和同一计算预算下，真实粗标签监督 Router 是否优于只用任务损失训练 Router？

这是最先裁定的主门槛。

### 子问题 C：模型标签能否复现真实标签方向

只有 B 通过后，才比较冻结模型产生的伪标签与真实标签。伪标签至少应在任务、表征和专家因果效用三个层面复现同方向变化。

### 子问题 D：专门化是否具有功能而非仅几何意义

删除或替换专家后，匹配语义类别的损失是否比非匹配类别上升更多？若没有，就不能声称专家功能专门化。

## 6.3 主假设与最强竞争解释

**主假设**：已有语义能力提供稳定粗标签；语义监督只训练 Router，Router 按类别分配数据；各 LoRA 专家通过所接收样本的任务损失形成差异化更新，因此得到条件功能专门化。

**最强竞争解释**：语义标签只提高了路由可预测性；所有 LoRA 专家学习的仍是相同函数，任务收益来自额外参数、数据分组或正则化。

能区分二者的关键观察是选择性专家效用，而不是 Router 准确率。

# 第七部分　建议的最小模型、数据与 Baseline

## 7.1 模型选择

### 学生基座

优先使用 **Qwen3-0.6B-Base**：

- 模型规模足够小，适合快速参数高效适配；
- Base checkpoint 便于区分“预训练已有能力”与后续适配造成的变化；
- 基座冻结后，只训练 Router 与 LoRA 专家，显存和检查点成本可控。

### 语义标签源

同时做两个不训练的入口审计：

1. Qwen3-0.6B-Base；
2. Qwen3-0.6B Post-trained 版本。

若 Base 的语义标签不足而 Post-trained 版本通过，应把后者称为“冻结语义教师”或“同系列后训练教师”，不能声称标签完全来自 Base 自身。

## 7.2 立即可用的数据

36 小时内最有效的是复用已有自然语言层级数据和代码，而不是重新搜集大规模语料。

### 首选：复用 E03 的 CLINC150 流程

CLINC150 天然具有“粗领域—细意图”两级结构，可直接审计：

- 粗语义标签是否可稳定发现；
- 粗语义路由是否帮助细意图任务；
- 同一粗领域内细类表示是否改善；
- 专家删除是否只伤害匹配领域。

但必须先打开 E03 原协议，确认任务目标不是简单复述同一个路由标签。若模型输出就是粗标签，语义路由监督会与任务标签重合，实验不再能够回答当前问题。

### 数据切分要求

- 训练、验证、测试按表达模板或近重复簇切分，不能随机拆分近义句；
- Router 与标签生成器只能看到输入，不得读取答案词元；
- 类别均衡，或显式报告每类样本量与宏平均指标；
- 伪标签在训练前冻结，第一轮不允许边训练边刷新；
- 测试真标签只用于评价，不参与阈值或类别命名调整。

## 7.3 标签生成方法

不要继续把一个 PCA 方向直接当成语义标签。先使用“模型语义判别”这一最直接操作化：

1. 为每个粗类别准备固定的类别名称和一句自然语言定义；
2. 对每个输入，计算模型在固定提示下生成各候选类别描述的长度归一化对数似然；
3. 选择得分最高的类别作为伪标签，用第一名与第二名的分差作为置信度；
4. 使用两个等价提示模板和两个输入改写视图，检查标签稳定性；
5. 低置信度样本不用于伪标签路由，单独报告覆盖率。

这一步使用了人给定的类别描述，严格说属于**语义先验引导的弱监督**，不是纯无监督。真正的无类别名自发现应作为后续实验，不能在第一步混在一起。

## 7.4 最小架构

第一轮只做粗粒度，不同时上完整粗细树：

- 冻结全部 Qwen 基座参数；
- 在一个预先选定的中后层 MLP 线性映射中加入一个公共 LoRA 与若干粗类 LoRA 专家；
- 使用序列级 Top-1 Router，Router 输入取**答案前、最后一个输入 token 的隐藏状态**；
- 语义分类损失只更新 Router；
- LoRA 专家只通过被路由样本的任务损失更新；
- 公共 LoRA 对所有样本生效，专门 LoRA 仅对被选类别生效；
- 第一阶段不使用 RL，不刷新伪标签，不增加表示对比损失。

总损失为

\[
\mathcal L
=\mathcal L_{\mathrm{task}}
+\lambda_{\mathrm{route}}\mathcal L_{\mathrm{route}}
+\lambda_{\mathrm{bal}}\mathcal L_{\mathrm{balance}},
\]

其中 \(\mathcal L_{\mathrm{route}}\) 的梯度必须停在 Router，不进入基座与 LoRA 专家。

## 7.5 Baseline 分层

### 主因果 Baseline

**完全相同的专家架构和训练流程，但令 \(\lambda_{\mathrm{route}}=0\)，只通过任务损失训练 Router 与专家。**

这个 Baseline 回答“语义监督本身是否有效”，优先级最高。

### 实用 Baseline

**单一 Dense LoRA**，匹配训练 token、训练步数和活动 LoRA 参数量。它回答多专家结构是否比普通参数高效微调有实际价值。

### 结构 Baseline

**平铺 MixLoRA**，匹配专家总参数和每样本激活专家数。它回答层级或语义结构是否优于普通多 LoRA 路由。

### 必要负对照

- 打乱语义标签；
- 随机但负载匹配的固定路由；
- 只增加等量 LoRA 参数、没有语义路由；
- 强制均匀负载但不使用语义标签。

### 文献对比 Baseline

进入论文阶段后，至少需要与 MixLoRA、HMoRA、MoELoRA 和 SAMoRA 比较。特别是 SAMoRA 已经直接研究语义感知 Router，因此你的区别必须落在模型自产层级标签、渐进生长和选择性因果效用，而不能只写“语义对齐专家”。

# 第八部分　表征、Router 与专家功能的分析方法

## 8.1 被测对象必须分开

对选定层 \(\ell\)，定义：

- 原始冻结表示：\(h_\ell\)；
- 被选专家残差：\(\Delta h_{e,\ell}\)；
- 有效表示：\(h'_{\ell}=h_\ell+\Delta h_{e,\ell}\)。

完整隐藏状态往往被公共基座主导，因此还要单独分析 \(\Delta h_{e,\ell}\)。否则不同专家的真实差异会被大幅公共分量掩盖。

## 8.2 三类必要指标

### A. 标签入口与 Router 指标

- 粗标签宏平均 F1 或平衡准确率；
- 归一化互信息、调整兰德指数和类别纯度；
- 类别覆盖率、预测熵、最大类别占比；
- 不同提示、改写和随机种子下的一致率；
- Router 准确率、熵、负载和路由切换率。

这些指标只说明标签和分发是否稳定，不说明专家学到了功能。

### B. 表征指标

1. **未见表达上的线性判别间隔**：使用训练集拟合的线性头，在模板隔离测试集上测量归一化间隔，重点报告低尾分位数，而不是只报告均值。
2. **条件组间/组内散度**：在固定粗类内比较细类组间散度与组内散度，避免粗类差异掩盖细类结构。
3. **表征坍缩比**：

\[
RC=\operatorname{Tr}(\Sigma_W\Sigma_B^\dagger).
\]

其中 \(\Sigma_W\) 是类内协方差，\(\Sigma_B\) 是类间协方差。较小数值通常表示类内变化相对类间变化更小，但它受类别不平衡、尺度和伪逆稳定性影响，只能作为辅助指标。
4. **专家残差子空间**：比较不同 \(\Delta h_e\) 的主角度、中心方向与跨切分稳定性。不要把“角度更大”自动解释为“专家更有用”。
5. **冻结读出与重训读出分离**：既报告固定在训练前的读出是否改善，也报告允许重训线性 Probe 后的可读性，避免把 Probe 学习误当成表示形成。

### C. 功能专门化指标

对专家 \(e\) 和语义组 \(c\)，定义删除专家后的损失增量：

\[
\Delta_e(c)
=\mathbb E_{x\sim c}
\left[
\mathcal L(f^{-e},x)-\mathcal L(f,x)
\right].
\]

再定义选择性效用：

\[
S_e
=\Delta_e(c=e)
-\frac{1}{C-1}\sum_{c\neq e}\Delta_e(c).
\]

若 \(S_e>0\)，删除专家 \(e\) 对其匹配类别的伤害大于其他类别。平均 \(S_e\) 是比路由纯度更接近“功能专家化”的主指标。

还应做：

- 正确专家与错误专家交换；
- 强制所有样本走同一专家；
- 删除公共 LoRA 与删除专门 LoRA；
- 在匹配类别和非匹配类别分别报告任务损失；
- 比较专家更新梯度在类内与类间的相似度。

## 8.3 结果的四种解释分支

| 观察 | 允许结论 | 不能声称 |
|---|---|---|
| 真实标签不优于同架构任务损失组 | 当前实现没有建立语义监督作用，停止伪标签路线 | 不能继续解释标签发现、去粗或自演化 |
| 真实标签改善表征，但任务与选择性效用不改善 | 语义监督能形成几何分组 | 不能称为有用的专家专门化 |
| 真实标签改善任务和选择性效用，伪标签失败 | 专门化机制可行，瓶颈在标签入口 | 不能声称模型能自我演化 |
| 真实标签通过，伪标签复现同向任务与选择性效用 | 模型语义信号可以指导参数高效专家化 | 仍不能推到大规模预训练、动态无限生长或 KV cache 加速 |

# 第九部分　Benchmark 比较策略

## 9.1 Benchmark 必须分成三层

### 第一层：主张对齐的核心测试

核心 Benchmark 必须直接对应“语义路由是否形成有用专家化”：

- 未见表达/改写上的目标任务性能；
- 逐粗类、逐细类的宏平均结果；
- 选择性专家效用；
- 语义标签入口稳定性；
- 表征低尾间隔。

这是论文主表，不应被通用 Benchmark 取代。

### 第二层：一般能力守卫

在 0.6B 模型上，应选择能够产生非地板信号且成本较低的任务，例如：

- LAMBADA；
- PIQA；
- HellaSwag；
- ARC-Easy；
- OpenBookQA；
- SciQ。

若训练目标是指令响应，再增加 IFEval。MMLU 对 0.6B Base 可能接近地板，不适合作为首要选模指标，但可以作为补充报告。

### 第三层：系统和资源指标

- 可训练参数量；
- 每个样本的活动 LoRA 参数量；
- 训练 token 与步数；
- 峰值显存；
- 训练吞吐；
- 推理延迟；
- 路由附加开销。

只有实际实现了 KV 分区和稀疏访问，才能报告 KV cache 节省；不能从专家数直接推算。

## 9.2 公平比较的固定项

所有条件必须匹配：

- 相同基座 checkpoint；
- 相同 tokenizer 与输入格式；
- 相同训练数据顺序；
- 相同训练 token 和最终 checkpoint；
- 相同优化器、学习率日程和批量；
- 相同或明确报告的总参数、可训练参数与活动计算；
- 至少两个配对随机种子；
- 同一测试脚本和解码设置；
- 数据去重、污染检查和模板隔离切分。

报告绝对分数、相对基座增量以及置信区间。只报告最好 seed 不可接受。

## 9.3 Benchmark 不能替代机制证据

即使公开 Benchmark 提高，也可能来自额外参数、训练 token 或正则化；即使路由标签更纯，也可能没有功能收益。因此，公开分数与专家反事实干预必须同时出现。

# 第十部分　36 小时执行规划

## 10.1 总原则

只推进一个因果门槛：

> **真实粗语义标签监督 Router，是否在预训练小模型上形成比同架构任务损失组更强的选择性专家效用？**

所有后续工作都由这个门槛决定。

## 10.2 时间表

### 0—2 小时：锁定对象与已有证据

- 打开 E03 与 E04 的原协议、配置和结果；
- 明确 E03 使用的 Qwen checkpoint、Router 输入位置、标签方法、任务目标和失败数值；
- 冻结新实验只改变的变量：标签入口和/或语义起点；
- 写下一句不能改变的核心问题与主指标 \(S_e\)。

**产物**：一页实验合同，不写代码前先固定条件。

### 2—6 小时：无训练语义入口审计

对 Qwen3-0.6B-Base 与 Qwen3-0.6B Post-trained 各做：

- 答案前隐藏状态线性可读性；
- 候选类别描述似然打分；
- 两个提示模板、两个改写视图的一致性；
- 粗标签宏 F1、覆盖率、熵和置信度。

**停止条件**：两种模型都不能稳定超过当前无监督标签方法，则先修正数据或标签定义，不进入专家训练。

### 6—10 小时：实现与公平性 Smoke Test

只搭建一个粗类 Router + 公共 LoRA + 粗类 LoRA 专家：

- 验证基座确实冻结；
- 验证语义损失只更新 Router；
- 验证未选专家无梯度；
- 验证各条件参数量、活动参数和 batch 完全匹配；
- 用极小数据过拟合，确认真实标签 Router 能达到高准确率；
- 检查没有答案泄漏。

### 10—20 小时：真实标签主比较

运行两个配对种子：

1. 同架构任务损失组；
2. 真实粗标签监督 Router 组；
3. 打乱标签组可在同一代码路径追加。

第一眼只看：

- 未见表达目标任务；
- 平均选择性专家效用 \(S_e\)；
- 一般能力守卫；
- Router 是否坍缩。

**停止条件**：真实标签组在两个种子上都没有同向改善，则本轮失败，不运行伪标签。

### 20—26 小时：模型标签组

仅在真实标签通过后：

- 冻结前 2—6 小时选定的标签器；
- 使用固定伪标签和置信度筛选；
- 保持其余设置与真实标签组完全一致；
- 报告相对真实标签上界恢复了多少方向，而不是只与任务损失组比较。

### 26—31 小时：机制分析

- 原始表示、专家残差和有效表示的低尾间隔；
- RC 与条件组间/组内散度；
- 正确专家删除、错误专家交换和强制单专家；
- 类内/类间梯度相似度；
- 逐类别失败样本检查，排除标签词或模板捷径。

### 31—34 小时：Benchmark 守卫

在最终 checkpoint 上运行轻量一般能力套件。只需要确认没有明显整体退化，不应在本轮做大规模调参。

### 34—36 小时：形成组会闭环

按照以下顺序写结果：

1. 问题；
2. 真实标签主比较的直接数值；
3. 选择性专家效用；
4. 伪标签是否复现；
5. 表征证据；
6. 一般能力守卫；
7. 当前允许结论；
8. 不能声称；
9. 唯一下一决策。

## 10.3 36 小时后的唯一决策

- **真实标签失败**：停止该实现，回到 Router 监督位置、专家容量或任务可辨识性，不讨论自标签。
- **真实标签成功、伪标签失败**：下一周期只解决标签入口，不改专家架构。
- **二者都成功但无选择性效用**：说明只是标签化路由，不是功能专门化；下一周期改功能目标或专家训练信号。
- **二者都成功且有选择性效用**：才进入细粒度分裂和标签动态刷新。

# 第十一部分　Post-training 需要立即掌握的知识与实验手法

## 11.1 必须掌握的概念

1. **监督微调（SFT）**：用指令—回答示范教模型产生目标行为；理解只在回答 token 上计算损失、数据混合和格式一致性。
2. **参数高效微调（PEFT）与 LoRA**：冻结基座，用低秩增量承载任务更新；理解 rank、注入位置、缩放、可训练参数与活动参数的区别。
3. **偏好优化**：理解偏好对、参考模型、DPO 与 RLHF 的区别。当前研究不需要立即实施。
4. **强化学习与可验证奖励**：理解策略采样、奖励、KL 约束和信用分配；只有当专家效用无法用监督目标直接表达时再考虑。
5. **数据课程与混合**：样本质量、类别比例、难度与顺序会改变训练结果，不能把所有收益归因于架构。
6. **灾难性遗忘与一般能力守卫**：目标任务提高的同时检查基座能力是否退化。
7. **评价污染与切分**：近重复、模板和答案格式可以制造虚假收益。

## 11.2 必须掌握的实验手法

- 配对随机种子与相同数据顺序；
- 参数量和活动计算匹配；
- 真实标签上界、伪标签、打乱标签和任务损失对照；
- 伪标签置信度、覆盖率与稳定性；
- 冻结/停止梯度检查；
- OOD 表达和模板隔离；
- 宏平均与逐类结果；
- 配对 Bootstrap 置信区间；
- 专家删除、交换与强制路由；
- 原始表示、残差表示和有效表示分离；
- 公开 Benchmark 只作外部守卫，不替代机制实验。

# 第十二部分　立即扫读的奠基性与最近相关论文

## 12.1 第一优先级：今天必须扫读

### P1. LoRA: Low-Rank Adaptation of Large Language Models（Hu et al., 2021，arXiv:2106.09685）

**要回答的问题**：低秩增量怎样接入冻结权重；训练参数、显存与功能变化怎样区分；为什么它适合当前低算力研究。

**重点看**：方法公式、注入位置、rank 消融、权重更新子空间分析。

### P2. MixLoRA: Enhancing Large Language Models Fine-Tuning with LoRA-based Mixture of Experts（Li et al., 2024，arXiv:2404.15159）

**要回答的问题**：多 LoRA 专家、Top-k Router 与负载均衡的标准 Baseline 是什么。

**重点看**：架构、参数/活动计算匹配、多任务训练和 Router 指标。

### P3. HMoRA: Making LLMs More Effective with Hierarchical Mixture of LoRA Experts（Liao et al., ICLR 2025）

**要回答的问题**：已有层级 LoRA Router 做到了什么；你的粗细层级与它的任务级/词元级层级有何不同。

**重点看**：层级路由定义、未见任务泛化、辅助路由损失和 Baseline。

### P4. SAMoRA: Semantic-Aware Mixture of LoRA Experts for Task-Adaptive Learning（Shi et al., ACL Findings 2026，arXiv:2604.19048）

**要回答的问题**：语义感知 Router 已经如何匹配输入语义与专家能力；你的新点不能停留在哪里。

**重点看**：语义编码、专家键、路由相似度、语义匹配/正交正则和专家分析。

### P5. Tulu 3: Pushing Frontiers in Open Language Model Post-Training（Lambert et al., 2024，arXiv:2411.15124）

**要回答的问题**：现代开放 Post-training 如何组织 SFT、DPO、可验证奖励 RL、数据清洗、开发集与未见集评价。

**重点看**：完整训练顺序、数据配方、消融、去污染和评测协议，而不是只看总榜分数。

## 12.2 第二优先级：36 小时内按需阅读

### P6. Training Language Models to Follow Instructions with Human Feedback（Ouyang et al., 2022，arXiv:2203.02155）

理解经典 SFT → 奖励模型 → PPO-RLHF 三阶段，以及示范数据、偏好数据和在线 RL 的角色差异。

### P7. Direct Preference Optimization（Rafailov et al., 2023，arXiv:2305.18290）

理解为什么偏好学习可以转化为直接分类式目标，以及为什么 DPO 属于 Post-training 但不是在线 RL。

### P8. MoELoRA: Contrastive Learning Guided Mixture of Experts on PEFT（Luo et al., 2024，arXiv:2402.12851）

理解已有工作如何用对比学习减少随机路由并鼓励专家差异；防止把“专家表征不同”误当成新点。

### P9. Don’t Stop Pretraining: Adapt Language Models to Domains and Tasks（Gururangan et al., 2020，arXiv:2004.10964）

理解领域持续预训练和任务持续预训练；用于判断你的 NTP 续训究竟属于 Mid-training 还是 Post-training。

### P10. Midtraining Bridges Pretraining and Posttraining Distributions（Liu et al., 2025，arXiv:2510.14865）

理解 Mid-training 是近年来形成但尚未完全统一的术语：通常在预训练末段混入高质量、领域化或指令化数据，缩小预训练与后训练的分布差距。

## 12.3 第三优先级：当前不应优先实施

### P11. QLoRA（Dettmers et al., 2023，arXiv:2305.14314）

当 0.6B 之外的模型显存不足时再采用；当前 0.6B 不应为了量化而增加新的数值变量。

### P12. DeepSeek-R1（DeepSeek-AI, 2025，arXiv:2501.12948）

用于理解可验证推理奖励和多阶段 RL，但当前语义 Router 问题已有直接监督信号，不应先用 RL。

### P13. ReMix: Reinforcement Routing for Mixtures of LoRAs（Qiu et al., 2026，arXiv:2603.10160）

当你确认梯度式 Router 出现权重支配、且希望使用离散功能奖励训练 Router 时再读。它说明 RL 可以训练 LoRA Router，但不是当前第一步。

# 第十三部分　认识更新

## 13.1 从当前失败中应得到的更新

旧实验失败不应解释为“表征里没有语义”，更准确的结论是：

> **从头训练的微型模型尚未形成稳定语义分类能力；即使最终层包含与真实标签相关的信息，当前无监督标签提取方式仍不足以形成可用的 Router 监督。**

“相关信息存在”“线性或语义可读”“标签稳定”“能训练 Router”“专家产生功能收益”是五个不同门槛，不能跳步。

## 13.2 从 Pre-training 转向预训练后适配的更新

研究问题没有从“表征”转成“只做工程微调”。新的问题更精确：

- 预训练提供什么可用语义入口；
- 后训练怎样把这种入口转成数据分配；
- 路由分配怎样塑造 LoRA 残差空间；
- 几何差异何时变成功能专门化；
- 何时可以从外部先验转向模型自产标签。

这比直接改变整个预训练范式更适合当前算力，也更容易形成可证伪证据链。

## 13.3 最终主张边界

即使最小实验成功，当前最多只能声称：

> 在一个固定的小模型、固定层级任务和参数高效适配设置中，来自冻结模型的语义标签能够改善 Router 的数据分配，并使 LoRA 专家获得对匹配类别更强的选择性任务效用。

仍不能声称：

- 该方法提高大规模预训练效率；
- 模型能够完全无监督地发现开放世界语义树；
- 所有长尾语义彼此正交；
- 专家结构能够无限自演化；
- 语义 Router 自动降低 KV cache 成本；
- 结果已经推广到大模型、开放域数据或 RL 阶段。

# 第十四部分　下一次组会建议汇报的四句话

1. **问题**：已有语义能力能否作为 Router 的监督入口，使参数高效专家形成真正的功能专门化？
2. **当前纠偏**：从头两三层模型没有语义分类能力，因此旧伪标签失败不能直接否定机制；下一步使用冻结 Qwen3-0.6B，并先审计 Base 与 Post-trained 的语义入口。
3. **主实验**：在相同 LoRA 专家树和计算预算下，只比较是否用真实粗标签监督 Router；专家仍只接收任务损失，首要指标是删除专家后的类别选择性损失增量。
4. **下一决策**：只有真实标签稳定优于任务损失组，才测试模型伪标签；否则停止自标签与细粒度生长。
