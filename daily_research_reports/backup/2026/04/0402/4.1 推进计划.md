# 4.1 推进计划

## 0. 本轮目标

本轮不是继续泛泛讨论 `quadratic` 是否更强，而是把当前新增的 4.1 子问题收束成一条清晰主线：

1. 二阶项 / 方差信息到底反映了数据中的什么本质信息。
2. 这些方差信息里，哪些可能与 MoE 的专家分发强相关。
3. “专家专一性 -> 低秩性”的联系需要更强理论解释。
4. 需要一个因果验证路径，确认我们设计的方法真的用到了与语义 / domain 相关的二阶结构。
5. 正在训练的新方法需要同步训练进展、收敛性和 load balancing。

这轮推进的重点不是立刻得出最终结论，而是把：

- 理论解释
- 机制验证
- 工程训练进度
- 下一步实验入口

统一成一套稳定执行方案。

---

## 1. 当前唯一 bottleneck

当前唯一 bottleneck 是：

`我们还没有把“二阶项为什么有意义”说清楚，也还没有证明当前方法真正利用了与 MoE 分发相关的二阶信息。`

因此，这轮所有讨论和实验都应服务于这个问题，而不是再扩展新的 router 故事线。

---

## 2. 本轮要和 Theory Agent 讨论什么

本轮和 theory agent 的讨论，不要直接跳到实现，而要先完成三层收束。

### 2.1 第一层：定义修复

目标：
- 明确“按方差分发”到底是什么意思。
- 明确“当前 quadratic / second-order method 到底按什么分发”。
- 明确“专家专一性”和“低秩性”分别是什么，以及它们的因果关系。

这轮必须问清楚的问题：

1. 二阶项到底反映了数据中的什么本质信息？
   - 局部离散度？
   - 语义概念激活的波动？
   - 某些 domain-specific directions 上的能量？
   - 还是只是频数 / 稀有词 / 风格差异？

2. 哪些二阶统计量才与 MoE routing 真正相关？
   - coordinate-wise variance
   - covariance between coordinates
   - projected energy on a subspace
   - class/domain-conditional covariance gap

3. 什么叫“按方差分发”？
   - 仅仅使用 `x_c \odot x_c` 不够
   - 必须明确是：哪些 variance / covariance 信息进入了 routing decision

4. 专家专一性与低秩性的关系如何严格表达？
   - `specialization` 是 assignment 结果
   - `low-rankness` 是几何后果
   - 需要更强的理论桥梁，而不仅仅是经验观察

### 2.2 第二层：机制解释

目标：
- 把当前方法定位清楚。

必须讨论：

1. 当前方法到底是：
   - diagonal second-moment routing
   - coordinate-wise centered-energy routing
   - 还是某种弱形式的 variance-aware routing

2. 真正更标准的 variance routing 应该长什么样：
   - `x_c^T Q_e x_c`
   - `||V_e x_c||^2`
   - 以及它们与当前实现的差异

3. 为什么如果二阶结构真的与语义 / domain separation 相关，就可能帮助专家分发：
   - 更清楚的域间分离
   - 更低的 subspace overlap
   - 更强的 assignment selectivity

### 2.3 第三层：收束成可交付实验问题

理论端最终必须把问题收成以下两条实验问题中的一条或两条：

1. `Causal Validation Question`
   - 如果用“按方差聚类 / 分组”的方式分析数据，是否真的能得到更清楚的 domain / semantic separation？

2. `Training Progress Question`
   - 当前基于二阶 / 方差改进的新 router，在训练中是否表现出更清晰的分发、收敛和负载均衡趋势？

---

## 3. 本轮要让 Theory Agent 最终输出什么

在允许多轮讨论的前提下，最后必须收束成一个 `Theory Pack`，至少包含：

### 3.1 Hypothesis

- H1：二阶统计中存在与语义 / domain separation 相关的信息，而不仅仅是噪声尺度
- H2：如果 router 真的利用了这类二阶信息，则 experts 会表现出更清晰的 assignment specialization
- H3：更清晰的 assignment specialization 会诱导更低的 expert 内部占用维度

### 3.2 Mathematical Modeling

- 当前方法的准确数学定位
- “按方差分发”的工作定义
- specialization / low-rankness 的因果桥梁
- 关键指标的正式定义

### 3.3 Experiment Design

最小应拆成两条：

1. `因果验证实验`
2. `训练进度与 routing 结构实验`

### 3.4 Conclusion/Update

- 当前能冻结什么
- 哪些仍是工作假说
- 哪些内容可以交给 experiment agent

最后还必须输出一张：

- `Theory -> Experiment Card`

---

## 4. 本轮要和 Experiment Agent 讨论什么

experiment agent 这轮不要重新理解项目，而是只执行两个板块。

### 4.1 板块 A：因果验证

目标：
- 汇报“用方差进行聚类 / 分组”的实验结果。

实验端要做的事：

1. 把已有数据表示整理成适合聚类 / separation analysis 的输入
2. 明确“按方差聚类”到底具体怎么做：
   - 用 diagonal variance feature
   - 用 covariance-derived feature
   - 用 projected energy feature
3. 比较：
   - 一阶特征方案
   - 二阶 / 方差方案
4. 汇报结果是否真的更能区分不同 domain / semantic groups

实验端需要回答的不是：
- 效果好不好看

而是：
- 二阶特征是否真的提供了更清晰的结构分离证据

### 4.2 板块 B：训练进度同步

目标：
- 汇报基于二阶 / 方差改进的 router 方法当前训练状态。

实验端要同步：

1. 当前训练到了什么 step
2. loss / 收敛情况
3. router 负载均衡情况
4. 当前输出的 routing structure 是否已经可分析
5. 哪些 checkpoint 值得做静态 mechanism audit

### 4.3 板块 C：结构指标测量

实验端要在结果里继续保留和扩展以下量：

1. assignment-side
   - token-to-expert statistics
   - per-expert top tokens
   - per-domain expert usage

2. geometry-side
   - `SI_e`
   - `r_{0.9}`
   - 必要时的 covariance overlap

3. mechanism-side
   - 二阶项贡献度
   - 如果可做，保留 `rho` 或同类 attribution 指标

## 5. 这轮推荐的 agent 分工

## 5.1 Theory Agent：先讨论，再收束

推荐节奏：

### Exploration Mode

先讨论这些问题：
- 二阶项到底携带什么信息
- 哪些方差信息与 routing 有关
- 专家专一性和低秩性的严格联系
- 当前 quadratic 的理论位置

### Convergence Mode

一旦满足下面条件，就收束：
- 已经能写出一句 `Single Decision Question`
- 已经能给出最小实验
- 已经能写 decision rule

然后产出：
- `Theory Pack`
- `Theory -> Experiment Card`

## 5.2 Experiment Agent：只接执行包

experiment agent 输入固定为：

1. 当前 checkpoint 摘要
2. 当前轮次 `Theory Pack`
3. `Theory -> Experiment Card`
4. 路径 / checkpoint / 输出目录

experiment agent 输出固定为：

1. `Experiment Pack`
2. 正式运行
3. `Result Pack`
4. `Experiment -> Theory Card`

## 6. 当前建议的两阶段实验顺序

### Stage A：静态因果验证

先做：
- variance-based clustering / grouping
- 一阶 vs 二阶特征分离能力对比
- 现有 checkpoint 的 token/expert 结构分析

这一步的目标是：
- 证明二阶结构中确实有可用于 routing 的信息

### Stage B：训练进度与机制同步

再做：
- 新 router 当前 checkpoint 的静态机制分析
- load balance
- expert specialization
- overlap / SI

这一步的目标是：
- 看训练出来的模型是否真的在朝理论目标靠近

## 6.1 推荐直接拆成两个实验 round

为了避免 experiment agent 一次拿到过多目标后 task drift，本轮建议直接拆成两个 round，在新的项目文件夹里顺序执行。

### Round A：Clustering / Separation Audit

这一轮只回答一个问题：

`如果显式构造一阶特征与二阶特征表示，二阶表示是否更能揭示 domain / semantic structure？`

这一轮建议交给 experiment agent 的任务边界是：

- 输入：
  - 固定好的特征来源 / checkpoint
  - 一阶表示方案
  - 二阶表示方案
- 输出：
  - clustering / grouping 结果
  - separation 指标
  - 可视化或表格
  - 结果解释

这一轮不要同时做：
- 训练
- load balance 分析
- interference 主结论

它只做静态因果验证。

### Round B：Interference / Geometry Audit

这一轮只回答一个问题：

`在当前训练得到的 router 上，不同 domain 的 routed activation 是否表现出更清晰的分离、更低的 overlap，以及更明确的 expert 几何结构？`

这一轮建议交给 experiment agent 的任务边界是：

- 输入：
  - 当前训练中的 checkpoint
  - expert activation / routed feature
- 输出：
  - `SI_e`
  - overlap / covariance overlap
  - `r_{0.9}`
  - per-domain expert usage
  - 必要的 token-level expert 结果

这一轮不要同时做：
- 新 router 训练
- 新 clustering 设计
- 新 benchmark 扩展

它只做 interference / geometry audit。

### 两个 round 的顺序

推荐顺序：

1. 先做 `Round A`
2. 再做 `Round B`

原因：
- `Round A` 更接近纯机制验证
- `Round B` 更接近当前训练模型的结构后果
- 先用 `Round A` 验证“二阶结构里确有相关信息”，再用 `Round B` 看“模型是否学会使用这些信息”，逻辑更干净

## 9. 一句话总结

本轮 4.1 的真正目标不是“再做一个二阶 router”，而是：

`把二阶项到底反映什么、哪些二阶信息与 MoE 专家分发强相关、以及这条线如何通过更专一的分发诱导更低秩结构，这三件事讲清楚并验证清楚。`
