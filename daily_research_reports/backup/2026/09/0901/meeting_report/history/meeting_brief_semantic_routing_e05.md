两个种子各完成 16 个正式训练条件，共 32 个最终条件。冻结 Base 作为额外的不训练参考。主要球面聚类与 Oracle 均完成全部四个消融格子；高斯混合与方向混合只运行注册的“冻结粗专家 + 去粗细 Router”格子。

### 0.2 是否真的分成两个训练阶段？

是。层级模型在两个阶段之间保存并重新加载检查点，重新建立优化器和余弦学习率计划；不是连续训练四轮后再人为切段。

| 设置 | 第一阶段：学习粗分发 | 第二阶段：固定粗分发，学习细分发 |
| --- | --- | --- |
| 数据遍历 | 2 epochs，30,000 次样本暴露 | 2 epochs，30,000 次样本暴露 |
| 参数更新数 | 每轮 59 次，共 118 次 | 每轮 59 次，共 118 次 |
| 批量 | micro batch 64，梯度累积 4，有效 batch 256 | 相同 |
| 训练对象 | 共享 LoRA、10 个粗专家、粗 Router、150 类任务头 | 共享 LoRA、150 个细专家、每个父类下的 15 路细 Router、任务头；粗专家按消融继续训练或冻结 |
| 固定对象 | Qwen3-0.6B-Base、所有细 Router 和细专家 | Qwen Base、粗 Router始终冻结；粗专家按格子决定 |
| 损失 | 150 类意图交叉熵；监督组再加 10 类粗路由交叉熵，权重 1 | 150 类意图交叉熵；监督组再加父类内 15 类细路由交叉熵，权重 1 |
| 优化器 | AdamW；LoRA/Router 学习率 \(3\times10^{-4}\)，任务头 \(10^{-3}\)，权重衰减 0.01，梯度裁剪 1.0 | 相同；重新开始 5 次更新的 warmup 和阶段内余弦衰减 |
| 阶段交接 | 每个 epoch 保存；开发集意图宏 F1 选择检查点；12/12 个粗阶段检查点均选择 epoch 2 | 24/24 个层级条件均选择第二阶段 epoch 2 |

Dense 与平铺条件没有层级交接，为匹配总数据遍历量，直接训练 4 epochs，即 236 次参数更新；8/8 个条件均选择 epoch 4。

实现中，语义路由交叉熵只直接更新 Router，不直接更新专家；当 Router 可训练时，任务损失还会通过被选中路径的软概率缩放向 Router 传梯度。第二阶段粗 Router 的 `requires_grad` 被关闭，因此不会再被任一损失更新。

## 1. 目的

检验冻结模型已有的自然语言语义，能否通过先粗后细的 Router 与 LoRA 专家形成更好的语义分发、专家功能和细粒度有效表征。

## 2. 假设

1. 语义监督应比任务损失和打乱标签形成更均衡、更符合真实领域的粗路由。
2. 若这种分发真正有用，匹配语义的专家应具有更高删除效用，并进一步改善细意图表征；否则变化可能只是路由外观或普通分区效应。

## 3. 分析方法

1. **先看分发：**比较任务损失、打乱标签、Oracle 和球面聚类的最大专家负载，以及路由与真实领域的归一化互信息。
2. **再看功能：**删除一个父专家，比较它对匹配领域和其他领域造成的任务损失增加，同时检查最终意图宏 F1 是否提高。
3. **最后看表征和层级特异性：**比较 Oracle/聚类相对同结构任务组的领域内细意图探针，并用平铺、打乱标签和 \(2\times2\) 消融排除容量与任意固定分区解释。

## 4. 结论

### 4.1 语义分发明确改善：语义监督避免了粗 Router 坍缩

任务损失层级组平均把 `97.2%` 的样本送给同一个父专家，与真实领域的归一化互信息只有 `0.027`。Oracle 把最大负载降到 `12.0%`，语义一致性升到 `0.517`；球面聚类把最大负载降到 `16.0%`，语义一致性达到 `0.287`。打乱标签虽然负载均衡，但语义一致性仍只有 `0.022`，因此“均衡”和“语义正确”被成功区分。

![语义分发与坍缩](../../figures/meeting_semantic_dispatch.png)

**怎么读：**左图越高表示路由越符合真实领域；右图越低表示越没有挤到单一专家。Oracle 和球面聚类同时满足两个方向，打乱标签只满足右图。

### 4.2 父专家形成了选择性效用，但没有转化成更高任务性能

删除匹配领域的父专家，相对删除其他父专家造成了稳定为正的额外损失：Oracle 均值 `0.00533`、95% 区间 `[0.00447,0.00619]`；球面聚类均值 `0.00303`、区间 `[0.00198,0.00409]`。因此在注册定义下，父专家功能门为 `WORK`。但是层级 Oracle 与层级球面聚类的最终意图 F1 只有 `90.63%/90.79%`，低于 Dense 的 `91.35%` 和平铺任务组的 `92.24%`。所以能够声称“形成小幅选择性功能”，不能声称“获得更好的最终任务性能”。

![专家效用与任务性能](../../figures/meeting_expert_utility_and_task.png)

**怎么读：**左图误差线整体高于零表示匹配专家确实更有作用；右图越高表示最终任务越好。当前左图通过、右图没有改善。

### 4.3 完整的“先粗后细塑造表征”尚未成立，失败集中在细专家写入

Oracle 相对同结构任务组的细意图探针提升为 `+0.191` 个 F1 点，但 95% 区间 `[-0.0003,+0.3866]` 跨零；球面聚类提升 `+0.066`，区间也跨零。层级 Oracle 与平铺 Oracle 的探针均值只差 `+0.008`，而打乱标签也产生同量级变化。与此同时，Oracle 细专家残差只有共享残差的 `0.52%--0.56%`，球面聚类也只有 `1.26%--1.39%`。这说明当前系统学会了“送到哪里”，但没有可靠地把细语义写入被送达的细专家表征。

![表征主判据](../../figures/primary_probe_effect.png)

**怎么读：**虚线零点表示不优于任务组；两个误差线都穿过零，因此不能判定 Oracle 或自监督层级带来了可靠的细表征改善。

## 5. 边界与唯一下一决策

- **已经理解：**语义监督能够形成更合理的粗语义分发，并建立平均意义上的父专家功能绑定；主要断点出现在细专家语义写入，而不是任务是否学会或粗 Router 是否可训练。
- **仍不能说：**不能声称当前方法优于平铺/Dense、细语义表征已经改善、冻结粗专家或去粗操作普遍有效，也不能把两个种子外推到一般自然语言任务。

**唯一下一决策：**在 MASSIVE 英语的 scenario—intent—slot 任务上运行一个非饱和的 Oracle 机制审计，并让槽位级语义信号直接检验细专家写入。

**完成标准：**Oracle 在注册的槽位表征或 span F1 上具有正的配对区间，同时细专家残差相对共享残差不再接近零；否则回到合成数据诊断目标函数与梯度路径。

**恢复动作：**先冻结 MASSIVE `en-US` 数据合同和 Oracle 最小对照，不先扩展聚类搜索或多语言。
