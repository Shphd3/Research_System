# Minimal Anchor Handwrite Draft

## 0. researcher judgment record

父问题：为什么 uniform slot setting 下，sparse top-1 MoE 不能自然形成 feature-to-expert specialization？

Round-1 结果：去掉 position embedding、移动 slot-B-target block 后，collapse 仍存在；但 routed hidden state 中 slot 信息可读。

关键发现：final routing 的 top-2 margin 大多由 common component 主导，且约 10 step 后 route 已稳定 lock-in。

正对照：slot-initialized setting 几乎都能形成 slot-level specialization，说明 specialization reachable。

当前解释：baseline 失败不是 missing slot signal，而更像 common-logit dominance + early top-1 lock-in。

下一步：查明 common-logit 是初始就大、训练长出，还是被 top-1 dynamics 放大，并测试它是否 causal。

## 1. Problem Definition

Parent problem:
Why does sparse top-1 MoE gating fail to stably form feature-to-expert specialization?

Sharper subproblem:
Given that slot information exists in routed hidden states and slot-specialization is reachable under favorable initialization, why does vanilla sparse top-1 MoE still collapse from random initialization?

Decision question:
Does collapse come from:
1. a common-logit advantage already present at initialization;
2. a common-logit advantage that grows during the first few optimization steps;
3. sparse top-1 lock-in that amplifies an early routing advantage;
4. or some artifact of the logit decomposition?


Not in scope:

- We do not claim a real-LM solution.
- We do not claim load balance equals feature specialization.

## 2. Physical Priors
P1. Slot signal exists in the routed hidden state.
Status: supported by Round-1 slot probe.

P2. Slot signal does not imply slot routing.
Status: supported by baseline collapse despite slot decodability.

P3. A common component can dominate sparse top-1 router logits.
Status: supported by logit decomposition, but not yet causal.

P4. Sparse top-1 routing can lock into an early routing basin.
Status: suggested by route stability after ~10 steps and by slot-init success, but timing and causality remain open.

## 3. Hypothesis

H1. Vanilla sparse top-1 collapse occurs because the router has a common-logit advantage at or before the early lock-in window, and top-1 training stabilizes this early expert assignment.

H2. Slot-initialized routing succeeds because initialization creates a slot margin larger than the common margin, placing the model inside a stable slot-specialization basin.

H1 supported if:
- common-logit gap is large at step 0 or grows before step 10;
- early common-logit ranking predicts final dominant expert;
- cancelling common-logit reduces collapse and improves slot NMI.

H2 supported if:
- slot-init runs maintain high slot NMI;
- interpolation from random init to slot init shows a threshold where specialization suddenly becomes stable;
- successful runs have slot margin > common margin before lock-in.

## 4. Mathematical Model
Objects:

- h_i: routed hidden state of token i
- s_i: slot identity
- b_i: B-token / template identity
- W_r: router weight matrix
- e_i: selected top-1 expert

Core decomposition:

之前我们简单构建模型：
$$h = c + r_slot + u_position + residual$$
现在我们需要构建随时间变化的表征拆分模型：
$$m_{s,p,t} = c_t + r_{s,t} + u_{p,t} + residual_{s,p,t}$$

where:
```text
s: slot
p: block position
t: training step
c_t: common component
r_{s,t}: slot component
u_{p,t}: block-position / prefix component
```

Sparse top-1 router:
$z_{i,e} = w_e^T h_i$,
$e_i = argmax_e z_{i,e}$
$score_e(m_{s,p,t})$
Logit decomposition:
$common_score_e(t) = score_e(c_t)$
$slot_score_{s,e}(t) = score_e(r_{s,t})$
$position_score_{p,e}(t) = score_e(u_{p,t})$

Observable metrics:

- slot-to-expert NMI
- per-slot route purity
- max-load / entropy
- top-1 logit margin
- component contribution to logit margin
- route switch time

## 5. Minimal Tests

E1. Exact-score decomposition audit
Question: Is the observed common dominance real under the actual router score, or an artifact of linear decomposition?

E2. Common-logit timing audit
Question: Is the common-logit advantage already present at step 0, or does it grow before lock-in?

E3. Common-source audit
Question: After removing position embedding, where does the common component come from: fixed B token, filler/template, residual mean, or optimization?

E4. Common-logit cancellation intervention
Question: If common score is removed from router decision, does vanilla sparse top-1 routing move toward slot-specialization?

E5. Slot-init basin audit
Question: Why does slot initialization succeed, and how close to slot geometry must the router be before specialization becomes stable?

## 6. Falsifiable Outcomes

Supported:
- exact router-score audit confirms common dominance;
- common-logit advantage appears before stable lock-in;
- common-logit cancellation increases slot NMI / purity without destroying accuracy;
- slot-init succeeds when initial slot margin exceeds common margin.

Weakened:
- exact router score does not show common dominance;
- common-logit grows only after collapse, not before;
- common cancellation removes common margin but routing still collapses;
- slot-init success cannot be explained by slot/common margin geometry.

Insufficient evidence:
- max-load decreases but slot NMI does not improve;
- only final heatmaps are shown without early trajectory;
- component decomposition has large reconstruction error;
- accuracy changes confound routing interpretation.

## 7. Current Evidence

P1 Baseline:
No-position, moving-block baseline still collapses.
Task accuracy reaches 1.0, but routing concentrates on a small number of experts.

P2 Representation:
Routed hidden state contains slot information.
Slot identity is decodable from h_B, including held-out positions.

P3 Logit decomposition:
Using h = c + r_slot + u_position + residual, final routing is mostly common-component dominated.
Final 290/320 cells are common-dominant.
Stable lock-in occurs after about 10 optimization steps.

P5 Positive control:
Slot-initialized runs almost all produce slot-level specialization.
This suggests slot-specialization is reachable, but not naturally discovered by vanilla random initialization.
