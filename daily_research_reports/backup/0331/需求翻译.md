1. Experiment Goal Translation

- 要更新的假说 ：主更新对象是 H4，次级更新 H2 / H6。 MoE - 迭代状态存档 v6.1:L44-L49
- H4 的精确定义 ： quadratic_nosvd_debias 只有在更低 SI 真能转化成更低 forgetting 时，才算对 CL 具备结构必要性。 v6.1:L46-L48
- 要区分的两个 competing explanations ：
  - 解释 A ： acp_lite 的一阶 mean-direction buffering 已经足够，低 SI 不会显著减少 forgetting。 v6.1:L101-L103
  - 解释 B ： quadratic_nosvd_debias 的低 SI 代表真实 anti-forgetting structure，因此在顺序学习里更能保住旧任务性能。 v6.1:L101-L104
- 成功意味着什么 ：若 quadratic_nosvd_debias 在 two-task sequential test 中得到更小的 ΔAcc_A ，且 Avg_after_B 没有明显恶化，则支持“低 SI 兑现成抗遗忘收益”，H4 升为 support。 v6.1:L136-L142
- 失败意味着什么 ：若 acp_lite 的 forgetting 不差于甚至优于 quadratic_nosvd_debias ，则 H4 被削弱或证伪，quadratic necessity 主线应关闭。 v6.1:L140-L142
- 本实验的最小判决口径 ：优先输出 Acc_A_after_A / Acc_A_after_B / ΔAcc_A / Avg_after_B ，再补 ACC / BWT / Forgetting 。 Continual Learning 评测调研与执行建议:L64-L80

  - accuracy_matrix.json
  - cl_metrics_summary.json
  - tables.md / final_report.md
- 核心 shape flow
  - 训练批次 ： source: [B, L] ， target: [B, L]
  - 模型输出 ： logits: [B, L, V] ，loss 由 train_qwen3_moe.py:L30-L55 的 chunked CE 计算
  - 路由辅助输出 ：若保留专家日志，通常是按层保存 top1 / topk expert labels，语义上可视为 [B, L] 或 [B, L, K_top]
  - 两任务准确率矩阵 ：单个 model-seed-sequence 对应 R ∈ R^{2×2}
    - R[0,0] = Acc_A_after_A
    - R[1,0] = Acc_A_after_B
    - R[1,1] = Acc_B_after_B
  - 跨实验汇总张量 ：可组织为 [num_models, num_seeds, num_sequences, 2, 2]
  - 派生指标 ：
    - ΔAcc_A = R[1,0] - R[0,0]
    - ACC_final = (R[1,0] + R[1,1]) / 2
    - BWT = R[1,0] - R[0,0]
    - F = max(R[0,0]) - R[1,0] （two-task 下与 forgetting 等价）

4. Risk Check

- 当前最大的“无法安全实现”缺口 1：Task A / Task B 的训练数据格式未定义
  - 理论文档只定义了顺序 CS -> Medical ，但没有明确训练集究竟是：
    - WOS 两个 domain 的 LM 语料子集
    - WOS 分类样本
    - 还是别的 continual corpus
  - 这会直接决定是否能复用 train_qwen3_moe.py ，因为它当前默认吃的是二进制 LM 数据目录， train_qwen3_moe.py:L78-L80 与 src/data_utils.py:L11-L18
- 缺口 2： Acc_A / Acc_B 的评测定义未冻结
  - 文档写了 Acc_A_after_A 等符号，但没有把 “A/B 的 accuracy” 明确绑定到哪一个 benchmark 或标签任务
  - 如果是 WOS domain task，需要新建专门 eval
  - 如果是 round0 下游 lm_eval，则 A/B 就不是 CS / Medical
  - 这两种语义不能混用；目前这是核心口径歧义
- 缺口 3：Task B 是否保留 optimizer / scheduler 状态未定义
  - 现有训练入口 --resume 会恢复 checkpoint 与 client_state。 train_qwen3_moe.py:L459-L467
  - 但理论没有说明 Task B 应该：
    - 连同 optimizer/scheduler 一起续训
    - 还是只加载模型权重、重置优化器
  - 这会显著影响 forgetting 和公平性
- 缺口 4： N 步数与评测 cadence 仍是占位符
  - v6.1 只写了 “Train on Task A for N steps / Task B for N steps”，没有给出具体值。 v6.1:L115-L120
  - 若不固定，结果可比性不足
- 缺口 5：当前理论没有规定显著性/判决阈值
  - “明显更小” 需要转成数值规则，例如：
    - 均值差 > 1 个 std
    - 或所有 seeds 中至少 2/3 一致
  - 不然最后很容易陷入解释性争议
- 最容易出错的工程点
  - sequence 方向混淆： CS->Medical 与 Medical->CS 的指标字段容易写反
  - checkpoint 污染：after A 与 after B 若共用同目录，易误评估
  - 评测口径漂移：不同模型 / seeds 若用了不同任务样本，会破坏公平比较
  - resume 逻辑误用：若 Task B 没接到 Task A 的最新 checkpoint，会变成独立训练而非 continual training
  - 硬编码路径： run_moe.sh 的 DATA_DIR 是写死的， run_moe.sh:L16-L20
  - 数值问题：若 domain 数据规模差异很大， ΔAcc_A 容易被 sample count 差异污染
- 因此当前可安全实现的边界
  - 可以安全实现 ：实验骨架、目录结构、总控脚本、CL 指标汇总器、报告模板
  - 暂时不能安全实现 ：最终 end-to-end 训练与结论判决，直到下面两件事被冻结：
    - Task A/B 的训练数据来源与格式
    - Acc_A/Acc_B 的评测定义
