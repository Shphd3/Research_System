## 目的

我们想回答：**长尾信息为什么学得慢？怎样的分工能让它学得快，又不伤通用能力？** 本次回应老师的三个问题：11/4“理想分类为什么能帮长尾学习”；11/6“为什么信噪比高就能加大学习率”；11/6“判别 feature 为什么不随粒度变细而降频”。

## 先定义要用到的对象

- **一步更新实验。** 取已训练 33B token 的 8 层 MoE（每层 8 个 expert，每个 token 选 2 个）。冻结全部参数，只允许最后一层（block 7）第 7 号 expert 的 FFN 走一步普通 SGD：参数 ← 参数 − η·梯度。走完立刻精确恢复。η 是步长（学习率）。
- **A、B 两组 token。** 用 SAE（把最后一层 router 的输入拆成 30000 个稀疏 feature 的字典，每个 token 激活 32 个）找出“哪些 feature 经常一起出现”，把这个 expert 收到的 token 聚成 8 簇。B 是最大的一簇，A 是与 B 最不像的一簇；B′ 是与 B 同簇、但来自不同文档的 token。用 A（或 B′）的梯度走一步，看 B 在留出文档上的损失变化 ΔL_B。负数是帮助，正数是伤害。
- **n** 是一个 minibatch 里的 token 数；**ḡ** 是用几千个 token 求出的平均梯度；**ĝ** 是只用 n 个 token 求出的单 batch 梯度。
- **SNR（信噪比）**：平均梯度的能量 |ḡ|² 与单 batch 梯度误差能量（梯度方差/n）的比值。

## 结论

**1. 我们现在认为，一步更新对别组数据的后果主要由“噪声项”决定，而不是由方向冲突决定。** 因为噪声伤害按 η² 增长、按约 1/n 下降，步长越过交叉点后很快压过方向带来的帮助（n=32、η=1/4 时约 17 倍）；跨组的方向项在 6 个簇对中都是小帮助，没有一个是伤害。证据到“局部因果”（单步、单 expert、单 checkpoint 的干预测量）。还不能说多步训练、Adam 或长期学习速度也如此。

**2. 原来以为“分到同一簇”就能提高信噪比，现在认为不是自动的。** 同簇 token 的方向帮助大约是跨簇的 48 倍，但它们损失高、gate 权重高，梯度噪声也大约是 5 倍，结果“帮助翻转为伤害”的步长 η\* 与跨簇几乎相同（n=32 时 0.016 vs 0.018）。真正能抬高可用学习率的是 n：η\* 随 n 近似成正比右移。证据到推导加事后估计；跨簇的交叉点没有在预先网格内被直接观测到。还不能说“集中同一信号”在训练中会提高最优学习率——这正是待批的 H2 实验。

**3. 原来担心“判别 feature 不随粒度降频”说明模型没学好，现在认为其中至少一半是正常现象。** 因为判别成员分两种：只在本父类出现的嵌套型很少见（Q 参考频率 MLP 0.48%），在其他父类也常用的复用型很常见（MLP 45.3%）；两个 SAE、三个阈值都同向。证据到“相容”（Qwen3-0.6B 受控文本上的事后描述）。还不能说“没学好”的解释被排除；它的检验需要更大模型或更晚 checkpoint，本轮未运行。

## 假设

- **H1（信噪比）**：我们认为长尾学得慢，主要因为信噪比低，而不是方向冲突。如果对，噪声项应为正、随 η² 增长、随 1/n 下降，跨组帮助在某个 η\* 处翻转，η\* 随 n 右移。如果错，噪声项不按 η²、1/n 变化，或跨组方向项在所有步长下都是伤害。
- **H2（分工集中信号）**：我们认为分工有用，是因为它把同一条长尾信息的信号集中到同一组参数，并把无关 token 挡在外面；分组依据应是“共同出现”，不是“频率相近”。如果对，新 expert 的收益随覆盖率 × 纯度单调上升，按频率分组不胜过随机。如果错，收益与覆盖率 × 纯度无关。**本轮只写了配置，未运行。**
- **H3（嵌套）**：我们认为“能区分”不等于“少见”。如果对，嵌套型判别成员低频、复用型不低频。如果错，两类频率没有差别。

## 实验分析

### H1：一步更新里的噪声项（33B MoE，MIG 约 10 分钟）

**设置。** 上面定义的一步更新；n∈{32, 64, 128}，每种 n 独立抽 32 个 minibatch；步长 η 从 1/32 到 4 取 8 个值。所有控制都通过：零更新的损失变化精确为 0，每次恢复后参数逐位相同。

**关键数字。**

| 量 | 跨簇 A→B | 同簇 B′→B |
|---|---|---|
| 噪声项对 log η 的斜率（n=32/64/128） | 2.06 / 2.04 / 1.95 | 2.17 / 2.01 / 2.02 |
| 噪声项对 log n 的斜率（η=1） | −1.18 | −0.99 |
| 方向项 g_B·ḡ（z 值） | 5.7×10⁻⁵（1.28） | 2.7×10⁻³（5.2） |
| 单 batch SNR（n=32 → 128） | 0.006 → 0.024 | 0.004 → 0.018 |
| 推导的 η\*（n=32/64/128） | 0.018 / 0.036 / 0.057 | 0.016 / 0.022 / 0.048 |

![噪声项标度](figures/fig1_noise_term_scaling.png)

读图：纵轴是“单 batch 走一步的平均伤害”减去“平均梯度走一步的伤害”，即噪声项。三条线平行、斜率贴着虚线 2；n 翻倍，线整体下移约一半。

**为什么会这样。** 单 batch 梯度等于平均梯度加一个随机误差，误差的方差是“单 token 梯度方差 / n”。误差的平均值为零，所以它不改变一阶的帮助或伤害；但 B 的损失在当前点是向上弯的，往任何随机方向走一步，二阶上都会让 B 变差，大小是 (η²/2)×(弯曲程度 × 误差方差)/n。这就是 η² 和 1/n 的来源，也是“信噪比高可以加大学习率”的数学含义：帮助随 η 线性增长，噪声伤害随 η² 增长，两者相等处就是 η\* = 2×帮助系数 / (噪声系数/n)，所以 n 越大（信噪比越高），η\* 越大。

![帮助到伤害的交叉](figures/fig2_help_to_harm_crossing.png)

读图：橙线是用平均梯度走一步，始终是帮助；蓝线是用单 batch 走一步的期望效果。n=128 时蓝线在 η≈0.075 才穿过 0，n=64 时在 0.042，n=32 时在网格之外更小处——交叉点随 n 右移。

**一个需要正视的事实。** 在这个 33B 状态下，单个 expert 的梯度几乎全是噪声：A 簇用 5376 个 token 求出的平均梯度，能量（0.0074）还不如它自带的抽样噪声（0.0077）。这就是跨簇方向项只有 z=1.28 的原因；DEV 切分上它甚至是负号。所以“跨组方向冲突”在这里既不显著，也不稳定。

**对原认识的更新。** 方向冲突不是这里的主因；在训练后期，每 token 的可学信号能量只有噪声的约 2×10⁻⁵，需要数万个同类 token 才能让信号压过噪声。分工要帮长尾，就要让同一条信号的 token 在同一组参数里累积起来。

**边界。** 一个 checkpoint、一个 expert、一层、单步 SGD。A、B 的初始损失（1.59 vs 4.30）和 gate 权重（0.20 vs 0.49）没有匹配，同簇/跨簇差别混有难度差别。簇是 SAE 共激活簇，不是“长尾 feature”。按预先判据，噪声部分支持，交叉点部分“不足”。

### H2：分工集中信号（NOT RUN）

本轮只写了 4×H100 的待批配置：冻结 33B MoE，在 block 7 加一个零输出初始化的新 expert，只改变“它收哪些 token”（共激活簇 / 等量随机 / 按频率分组 / 打乱簇标签），其余全同；每种策略 3 个学习率。读数是每个目标 feature 的覆盖率 × 纯度与其留出 token 的损失下降。约 1.5 小时（500 步、单种子的粗估）。

### H3：判别成员的嵌套度（CPU，复用 S13 缓存）

**设置。** Qwen3-0.6B 的两个 SAE；8 个父类、16 个细类的受控文本。“判别成员”沿用 S13 在开发集冻结的兄弟细类更替成员（一侧进 Top32、另一侧不进）。**嵌套度** = 它在全部 24 类文本中的出现里，有多大比例落在自己父类的三类文本中（随机水平 1/8）。

**关键数字。**

| SAE | 嵌套型 / 复用型 | Q 参考频率均值 | 差及区间 | 嵌套度与频率的秩相关 |
|---|---|---|---|---|
| Attention | 22 / 44 | 0.82% vs 8.98% | 8.2pp [7.2, 8.6] | −0.72 |
| MLP | 20 / 21 | 0.48% vs 45.3% | 44.8pp [42.8, 44.8] | −0.78 |

![嵌套度与参考频率](figures/fig_nesting_vs_frequency.png)

读图：右下的蓝点是嵌套型，几乎都低于 2%；左侧的橙点是复用型，MLP 的复用型集中在 30%–75%。MLP #8048 区分汽车/自行车，但嵌套度只有 0.15，参考频率 74.7%。

**为什么会这样。** 频率量的是“一个成员在多少种上下文里被用”；判别量的是“它在这一对类别之间是否不同”。嵌套型成员只服务一个父类，自然文本里遇到这个父类的机会有限，所以少见。复用型成员服务跨父类的通用成分，到处都用；它能区分汽车和自行车，只需在一侧进 Top32、另一侧没进，这与它在别处常用不矛盾。

**对原认识的更新。** 判别成员中复用型占一半以上（Attention 67%、MLP 51%），它们不降频是使用范围决定的。另一个意外：兄弟类的共享成员大多不嵌套（平均嵌套度约 0.18，接近随机水平 0.125），只有约 5% 是嵌套型。所以“共享成员被父类限住而偏低频”只对一小部分成立。

**边界。** 只有 8 个父类，嵌套度是粗估计；同作者模板文本；事后探索，开发集外的确认文本已在 S13 用过。

## 现场可能被问的问题

**问：噪声项按 η² 增长是数学必然，测它有什么意义？**
答：形式是推导出来的，但它在真实模型上是否主导、主导到什么程度，要靠测量。我们测到的是：n=32、η=1/4 时噪声伤害约为方向帮助的 17 倍（n=128、η=1/2 时约 9 倍），平均梯度本身都接近噪声底；这个量级不是推导能给的。

**问：为什么同簇的 η\* 没有更大？“分工提高 SNR”是不是错了？**
答：同簇的信号大，但噪声也大，因为这些 token 损失高、gate 权重高。SNR 由“同一信号被多少 token 重复”决定，不由“是不是同一簇”决定。分工要起作用，得让同一信号的 token 数（有效 n）变大，同时挡住不相关 token 带来的噪声。H2 测的就是这件事。

**问：跨组方向项 z=1.28，是不是说明根本不存在跨组帮助？**
答：不能这么说。6 个跨簇对的点估计全是帮助，3 个 z>2；主比较对只是太小、测不准。能说的是：没有看到显著的方向冲突。
