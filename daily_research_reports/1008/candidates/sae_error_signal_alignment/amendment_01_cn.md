# Amendment 01：Qwen 数值重放修复

**首个任务在 Qwen 数值资格检查处失败；H2 的数据、指标和判定不变。** 失败是测量实现的资格问题，不是 H2 非支持。S7fresh 的 16,384 个位置已完成采集；未分析这些梯度来调整第二次测试。

2026-10-08 08:40:51 UTC，ACP 确认 `pt-hsy9grzm` 已 `FAILED`。实际四卡均为 NVIDIA H100 80GB HBM3；原始资产和冻结 hash 已通过 preflight。四个 worker 的 Qwen 完整 hidden 与选定位置重放 hidden 的最大绝对偏差分别为 2.30e-5、2.67e-5、2.48e-5、4.58e-5，超过原定 2e-5；CE 偏差均低于 1.21e-5。没有产生合格 Qwen 主结果。

原实现只重放每条记录选出的 16 个位置，改变了 MLP 矩阵乘法的形状。其数学计算相同，但 FP32 实现可能因形状改变产生数值差异；这是待复核的故障解释，不是已证明的硬件原因。修正为按原生完整 batch×255 位置重放末 MLP、残差相加和 final norm，仅在 lm_head／CE 前选择目标位置，并从完整反传梯度中取同一批位置。hidden 检查现在覆盖完整 prefix，CE、δ 和参数梯度检查阈值均不放宽。

H2、两套资产、原生接口、1024 条文本、16 个位置、fit/test、输入选邻居、随机与 bootstrap seed、竞争对照、覆盖要求和判定分支全部沿用 [Protocol](protocol_cn.md)。额外三个 CPU 检查验证完整形状、逐记录不同位置以及未选择位置的零梯度；联合原有指标检查，共 11 项 CPU 测试通过。这仍不代替 GPU 数值资格检查。

原 [冻结登记](evidence/registration.json) 和原 config 保留；22 项原始源文件已逐项核对 hash 并保存在执行根目录 `registrations/v1_snapshot/`。原任务日志与 `failure.json` 不覆盖。修正版使用独立 `configs/h2_v2.json`、`configs/freeze_manifest_v2.json` 和新 run root，提交前重新登记真实 hash。图表模块只显示已登记统计，不改变主分析或科学判定。

研究者已要求“直接分析执行”“都测一下”。本修正执行该授权范围内的测量实现修复；不是新增科学条件或自动盲目重跑。旧任务终态已核验，允许一次有记录的修正提交，仍使用四卡 H100 reserved。新任务上限缩为 3 小时 45 分钟；为首任务保守预留 15 分钟，合计 GPU 预算不超过原 16 GPU 小时。若修正后资格仍失败，保留失败状态，不再自动换阈值或选择结果。
