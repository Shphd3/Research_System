# 实验理解、Protocol 审核与执行授权门

使用顺序：`AI 四段白话解释 -> 我确认或纠正 -> Protocol 审核 -> 单独授权执行 -> 我报告结果 -> AI 写 Daily Report`。

## 1. 执行前的四段白话解释

AI 必须先按以下格式回复，并同步写入本周期唯一活动
`focus_<problem>.md`。不使用未先解释的英文代号或指标名。

```text
1. 核心问题：
2. 实验目的：
   - 要把问题解决到什么程度
   - 依次回答哪些子问题
   - 什么算完成
3. 分析方法：
   1) ...
   2) ...
   3) ...（最多三条）
4. 结论：
   - 若支持：预期看到什么，能帮助回答什么，仍不能说什么
   - 若不支持或证据不足：预期看到什么，主线应怎样停止或改写
```

一个核心实验优先，最多三个。只为同一个 verdict 服务的随机对照、标签置乱、
稳健性检查和泄漏审计属于可信度护栏，不膨胀成新的核心实验。

## 2. 研究者确认

研究者返回 `CONFIRM`，或逐句 `CORRECT` / `BLOCK`。只有 `CONFIRM` 或研究者
改写后的明确确认，才允许把同一个设计写成可审核的 `protocol.md`。这一步不
授权实现或运行。

## 3. Protocol 审核

Protocol 必须保持 `DRAFT_NOT_EXECUTABLE`，直到问题、数据、方法、主指标、
Pass / Fail / Insufficient、可信度护栏、产物和执行范围全部逐块确认，且跨块
一致性通过。研究者对每个待定项返回 `CONFIRM`、`CORRECT` 或 `BLOCK`。

## 4. 单独执行授权

Protocol 设计获批后，仍需研究者明确授权以下某一范围：

```text
IMPLEMENT_ONLY / SMOKE_ONLY / EXECUTE_FULL_RUN
```

没有这条单独授权，不能写实现、提取新数据、打开密封确认集或运行实验。

## 5. 结果与 Daily Report

执行后，研究者先在 Focus 中完成：

```text
直接结果：
我的结论：
仍然不能说：
唯一下一决策：
```

AI 只核对数字、证据资格和逻辑边界。研究者确认后，AI 才从 Anchor、冻结
Protocol、Summary、Detailed 和该人类结论写自包含 Daily Report。原则是：
研究者能闭卷讲清问题、比较、结果和边界，AI 才把它扩成完整 story。
