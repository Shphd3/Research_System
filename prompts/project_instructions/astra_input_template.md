# Astra 回路 — 固定输入模板

> 外部模型（如 GPT-6 Astra）**读不到**本仓库、读不到执行工作区、读不到 canonical 记忆。
> 因此它只能做**有界输入的独立判断**，不能做**依赖状态的规划**。
> 每次调用照抄下面三段中的一段，填空后发出。**不要**把聊天记录贴给它。

## 适用与不适用

| 用它 | 不要用它 |
|---|---|
| 质疑一个已写明的边界 | 判断真实运行状态（它看不到执行工作区） |
| 找未被证据支撑的声称 | 回答「我们之前决定过什么」（它看不到记忆） |
| 提出最强竞争解释 | 决定下一步科学决策（那是研究者拥有的） |
| 把问题陈述转成四段式设计草案 | 直接产出可执行合同（须经 Protocol 审批） |

---

## 第 1 段 — 独立审阅（性价比最高）

```text
你是独立审阅者，不是执行者。下面是一份研究交接文件的三个片段。
你没有该项目的任何其它上下文，也不要去猜。

【边界 C】
<粘贴 continuation.md 的 C 段全文>

【完成合同 G】
<粘贴 G 段全文>

【当前状态 F】
<粘贴 F 段全文>

请只回答以下四问，每问不超过 5 条，每条必须指向原文或写「原文未说明」：
1. 哪些声称在给定的 F 与 G 之下**没有被证据支撑**？
2. 哪些边界**最可能被越界**，越界后的具体后果是什么？
3. 最强竞争解释是什么，它需要什么证据才能被排除？
4. 有没有**原文自相矛盾**或与「不可核验」状态冲突的地方？

约束：不要提出新的实验；不要给出下一步决策；不要评价写作风格。
只做质疑。凡是你无法从上述三段判断的，明确写「无法判断」。
```

## 第 2 段 — 设计草案（必须有依据的输入）

```text
你是研究设计助手。下面给你一个研究问题、已确认的边界、以及可用资料的清单。
你没有其它上下文。

【研究问题】<研究者亲自写的一段话，一句话到一段，不要贴聊天记录>
【边界 C】<粘贴 C 段>
【可读资料 B】<粘贴 B 段的表，不要附正文>
【可复用资产 H】<粘贴 H 段的表>

请输出一份**四段式**设计草案，严格用这四节：
1. Purpose（解决核心问题的哪一部分，以及为什么必须做）
2. Hypothesis（预测的对比、最强竞争解释、能把二者分开的结果）
3. Analysis method（比较什么、为什么这样比较就能回答问题）
4. Conclusion（执行前先写好分支：支持 / 不支持 / 证据不足，各自的结论与对当前问题的影响）

约束：
- 不要发明仓库里不存在的路径、文件或数据；需要什么就写「需要研究者提供」。
- 每条断言标注：直接结果 / 观测 / 解释 / 主张 / 推测 / 限制 / 决定。
- 输出标记为 `DRAFT_NOT_CANONICAL`。它不构成审批，也不构成下一步决策。
```

## 第 3 段 — 执行（由有仓库访问权的 agent 做，不是 Astra）

```text
执行 agent 的输入不是 Astra 的自由文本，而是：
1. continuation.md（当前入口，含 B 读取清单与 E 行动清单）
2. 研究者已确认的 Anchor / Protocol

执行 agent 必须：按 E 段行动并逐步核验；对照 canonical 源验证一切引用；
不加强任何声称；不代替研究者做科学决策。
```

---

## 使用纪律

1. **一段一用**，不要把三段混在一次调用里。
2. Astra 的输出**永远**是草案或质疑，**永远**要经研究者裁决后才进入 canonical 记录。
3. Astra 的产出**不进** `.research/memory/`、**不进** `PROJECTS.md`、**不进** Anchor 或 Protocol，
   除非研究者明确要求并由有仓库访问权的 agent 落笔。
4. 若 Astra 给出的路径或文件在仓库中不存在，**以仓库为准**，不要迁就它的说法。
