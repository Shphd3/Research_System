# 任务相关的中继监督与普通主头收益

## 摘要

A13 找到了一个受控的充分条件：更早的未来式监督能够提高普通
next-token 主头，但必须同时满足三点——监督目标描述最终答案所需的
变量；监督落在答案必经的较早状态上；该状态确实被运输并由普通主头
使用。

在只改 relay（中继状态）一个辅助标签、其他目标全部相同的实验中，
用答案变量 \(A\) 监督 relay，相比用同词表、同词频、同样可预测但因果
无关的 \(B\) 监督：

\[
\bar R_{\mathrm{relay}}=0.2315\ \text{nats},
\qquad
\bar R_{\mathrm{bypass}}=0.0181\ \text{nats},
\]

结构必要性交互为

\[
\bar\Delta_R=0.2134\ \text{nats},
\]

95% 配对 bootstrap（重复抽取八个配对种子估计不确定性）区间为
`[0.1646, 0.2585]`，8/8 种子同方向。四个条件最终均 8/8 学会，且
relay 状态替换后普通主头 8/8 跟随供体答案。

这是一个固定训练预算内的 credit assignment（信用分配，即“答案损失
应该把哪一个较早状态往什么方向训练”）结果。它不是“NTP 看不到答案”
的结果：NTP 在晚一个位置仍会预测同一个答案，并且能够学会任务。

## 1. 最小模型

令 \(A,B\) 为两个同词表的值，答案为

\[
Y=A.
\]

较早的 relay 状态为

\[
S=f_\theta(A,B).
\]

在 `relay-required`（必须中继）条件中，答案只能通过

\[
\hat Y=g_\theta(S)
\]

获得；在 `bypass-available`（允许绕行）条件中，答案位置还可以直接
读取 \(A\)。

最终对照只在 relay 的一个辅助目标上不同：

\[
T^A=(x_2,x_3,x_4,x_5,A),
\]

\[
T^B=(x_2,x_3,x_4,x_5,B).
\]

\(A\) 和 \(B\) 的词表、逐词频、位置、可预测性、头结构和损失权重匹配。
两者的任务因果作用不同：

\[
Y(\operatorname{do}(A=a),\operatorname{do}(B=b))=a.
\]

固定 \(A\) 改变 \(B\)，正确答案不变；改变 \(A\)，答案随之改变。

## 2. 我们为什么之前陷入瓶颈

过去混合了三个不同问题：

1. 模型能否形成并运输一个状态；
2. 模型能否根据晚到的 query（查询）从多个值中绑定正确值；
3. 更早的任务相关监督能否提高后续普通主头。

最初 carrier（载体任务）把三者一起测试，NTP 不稳定。移除 query
binding（查询绑定）后，单值 relay 通过所有门槛。这说明查询绑定是
后续独立任务属性，不是无害的实现细节。

第一次正式比较还犯了第二个错误：要求每一种训练目标施加后都必须
学会，才允许读取结果。但某个目标让模型更难学，本身就是处理效应；
用“处理后的能力”筛结果会把真实差异删掉。两个原实验仍保持
`insufficient`（证据不充分），随后新实验改为先用 NTP 独立验证载体，
再逐标签干预训练目标。

## 4. 当前能够回答：MTP 更适合什么任务

当前证据支持的不是“代码”或“长上下文”这个名字，而是以下性质的
合取：

1. 某个 future target（未来目标）包含最终答案需要的变量；
2. 该变量必须在较早状态形成；
3. 最终普通主头没有足够的局部绕行路径；
4. 状态运输和普通头读取本身可学；
5. 固定预算内，NTP 的稍晚信用路径还没有同样高效；
6. 提前目标可预测，不会引入过大的噪声或冲突。

以下情况优势应消失或缩小：答案可以局部直接得到；未来目标只是无关
变量；NTP 已经足够快；运输擦除状态；普通头不读取；未来目标条件熵
太高或全位置梯度相互抵消。

## 5. 为什么代码可能比普通文本更需要它：目前只是可检验假说

部分代码和规划任务更可能具备上述结构：

- 标识符、程序状态、约束或中间结果在很早处形成，执行后果在更晚处
  才出现；
- 后续精确 token 或执行结果必须使用该状态，局部同义线索较少；
- data flow（数据流）和 control flow（控制流）形成明确的状态运输路径；
- 中间变量错误会精确改变后续输出。

普通自然语言常有局部冗余、同义复述和多条绕行线索，但并非所有文本
都如此。因此正确预测是：

> 只有当匹配后的代码样本比文本样本包含更多“答案相关、必须运输的
> 延迟状态”时，MTP 才应当在代码上表现出更大收益。

本轮没有运行真实代码/文本对照，不能把这个预测写成结论。

## 6. 与 MoE Router 的关系

relay 状态未来可以成为 Router（决定 token 交给哪个专家的模块）的
候选输入，但前提是它能预测 held-out expert utility（在独立测试集上，
不同专家对最终损失的真实差异）。表征可读、几何更分离或 MTP 有收益，
都不能自动推出专家分工有用。

## 7. 结论边界与唯一下一步

已经建立：一个合成载体中的最小充分条件与反例。

尚未建立：一般 MTP、更远 token 距离、多证据组合、改写不变性、真实
代码/文本、长上下文、规划或 MoE 收益。

通过后再问提前任务相关监督能否在组合任务中保持收益。**
