## Frozen computation and comparison

`MoE` and `MoE_LB` both use a bias-free FP32 linear router from the 1,024-dimensional raw block-28 hidden state divided by the inherited TRAIN RMS scale to eight logits. A full softmax produces eight probabilities; select the top two distinct expert IDs and renormalize their selected probabilities to sum to one. Exact ties prefer the smaller ID. Every expert receives the complete scaled hidden state. The branch adds the weighted SwiGLU outputs times the same TRAIN scale to the original residual, then uses the unchanged frozen final normalization and tied output embeddings. There is no capacity cutoff, dropped token, noise or z loss.

The eight experts have the identical shape and per-seed initialization as the previous round: 25,165,824 parameters. The new router adds 8,192 parameters (total 25,174,016), initialized with independent `seed + 741103`, normal standard deviation 0.02. Both new arms share router and expert initialization and data order within seed. Expert down matrices start at zero, giving exact original Base output initially. Ordinary-MoE controls also learn mixture weights, whereas the previous feature router always averaged its two outputs at 0.5 each. Thus an old/new contrast changes router selection, mixture weighting and parameter count; it is not an isolated test of feature information.

For an effective batch of N valid answer-prediction positions, `P_i` is the mean full softmax probability of expert i and `f_i` is its count among the 2N selected assignments divided by 2N. Define `L_LB = 8 sum_i f_i P_i`. Assignment counts are detached; gradients flow through probabilities. Compute this once at the full effective-batch level, not separately averaged across microbatches. The raw balance loss equals one at uniform routing. The objective is answer CE plus alpha times this loss, with alpha 0 for `MoE` and 0.01 for `MoE_LB`. This is an explicit top-2 adaptation of [Switch Transformers equations 4–6](https://jmlr.org/papers/volume23/21-0998/21-0998.pdf); Switch originally defines top-1 fractions. The coefficient is a fixed conventional implementation choice under the requested controls, not tuned against any panel.

DEV is a fixed exposed review panel for this extension, not fresh confirmation. The existing frozen sparse features are used only to evaluate the same low/high feature definitions; the learned router receives no feature activations or future targets.
