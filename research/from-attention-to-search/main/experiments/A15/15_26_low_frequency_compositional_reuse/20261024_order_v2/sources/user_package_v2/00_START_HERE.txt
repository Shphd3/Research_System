订单系统与符号组合的 MoE 研究执行包 V2
版本日期：2026-10-24。用途：交给新 Agent 执行，供研究者次日检查与理解。

使用方法
1. 上传整个 ZIP 并让 Agent 解压。
2. 将 01_PROMPT.txt 全文作为新对话开场。
3. 次日先看 Agent 生成的 morning_readme，再按六个阶段看观察事实，不必先读所有日志。

用户已确认
- 一个订单系统贯穿六阶段。
- 由 Agent 按语义明确任务结构，不要求人为搭建具有真实中间接口的模型。
- 使用 Qwen3-0.6B 级别模型，4 卡 H100 reserved；没有人为规定的截止时间，按有限协议完成全流程。
- 附带此前符号组合版作为补充证据；不要重复询问已经确认的选择。
- 用户会自行开启 Agent。本包的生成没有启动任何训练或额外 Work/Codex 会话。

关键边界
任务标签和正确答案可以由明确规则生成，但这不等于人为指定模型内部模块，也不证明模型按该规则计算。
训练可以自动推进，不等待逐阶段人工审核；数据/实现问题必须修复。科学资格不足时，不应假造下游阳性结果。
全流程完成 = 六阶段均有执行结果或科学上不适用的证据记录，符号对照有结论，交付可复核。
全流程跑完不保证假设成立，也不保证一定在明早前结束。若仍运行，必须有真实的中间阅读包和剩余状态，不能写“全部完成”。

文件导航
01_PROMPT.txt：开场与权限范围。
02_ANCHOR.txt：导师直觉、当前问题、六个假设及边界。
03_DATA_PROTOCOL.txt：任务语义、数据划分、频率控制、标签与评价。
04_TRAINING_PROTOCOL.txt：父模型、干预、共享/分开、路由、符号补证。
05_EXECUTION_AND_AUDIT.txt：资源、门槛、修订、状态与验收。
06_MORNING_READING.txt：明早结果解释结构。
07_SEMANTIC_EXAMPLES.jsonl：自动核算的语义样例，仅用于理解与单元测试，不是正式数据集。
08_REFERENCE_ORACLE.py：纯 Python 参考判题器，不是训练脚本。
09_RESULT_MANIFEST_TEMPLATE.json：运行与交付状态模板。
10_CHECK_RESULT_MANIFEST.py：基本产物完整性检查器，不能代替科学审计。
legacy/：此前符号组合原包及原文，原样保留。其执行条款若与 V2 冲突，以 V2 为准；历史文本不改写。

相对于旧包的变化
主任务由抽象置换组合改为订单规则组合；补齐正常/慢/固定更新及共享/分开与路由诊断；保留符号任务但作为辅助而非冒充订单证据。
不另建人为模块化模型，不把语义上的共同处理直接等同于参数位置。
少量旧任务回放采用10%的设计默认值，同时设置无回放敏感性检查。这是本包的协议选择，并非声称用户曾指定该比例。
