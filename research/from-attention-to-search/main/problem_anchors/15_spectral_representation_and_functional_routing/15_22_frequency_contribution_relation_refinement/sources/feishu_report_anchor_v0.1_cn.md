# 从关系分组到频率优先的专家分工

**状态：讨论稿，等待研究者确认；不代表新实验已经执行。**
主方案已经确认：依据当前输入中的**原始末层贡献份额**选择频率段；相对常态校准为对照。具体分段、每段专家数和组内算法是下附 Protocol 的建议默认值，尚未批准。

## 一、接上上次组会：为什么继续研究这个问题

上次组会的共同问题是：**如果按频率组织内容，有限参数究竟能多学好多少内容，或者达到相同表现能节省多少预算？** 学长的理论工作尝试量化理想情形的收益；我们负责把可观察的表征结构接到实际分发与学习。二者相关，但一个几何指标或理论标度不能直接当作真实模型的容量倍数。

我们此前从 φ 共现关系出发形成候选组，检查其组内频率是否更接近。这里的 φ 是二元激活相关系数，不是解码贡献，更不是学习帮助或干扰。此前对照与建图偏好仍需限定，不能将“观察到同频倾向”升级为自然同频规律已经确证。

后续几轮共同说明：名单上的组织、token 实际分发、学习效果需要逐环对照。原始评分使低频名单几乎没有实际接收；校准可改善接收，但完整表征仍携带高频信息。冻结末层旁支的 DCLM 和 Tulu SFT 固定终点均未产生留出收益；Tulu 部分指标早期改善后反弹，提示训练预算可能影响结果，尚未确认根因。

**因此，本次调整是：把频率从关系分组的附带属性，提升为显式组织依据；在频率相近的范围内，再检验 feature 关系能否改善内容分工。** 不预设同频一定更好，也不预设异频一定有害。

## 二、目的

在固定参数与计算预算下，理解什么样的专家分工能够让模型学好并保留更多内容。

当前问题：**当前位置的上下文化表征中，不同频率 feature 的贡献组成，能否作为 token 到专家的分配依据？频率相近后，具体 feature 关系是否还提供额外价值？**

“当前位置”指模型用来预测下一个 token 的位置；它携带可见前文的信息，不只是当前词片 ID。低频指 feature 的命中频率，不直接等于罕见知识、细腻语义或学习困难。

## 三、机制直觉（一句话）

**先根据当前表征中哪些频率段的贡献更突出确定分工范围，再根据具体 feature 组成细分接收者，尝试避免只按词片或把所有低频内容堆给同一专家。**

这是候选机制，不是结论。频率一致不能保证共同学习相容；容量足够也不能保证有限预算内优化足够快。

## 四、待检验假设及解释边界

### H1：输入画像与词频之间的桥梁

低频 feature 的末层贡献份额，与当前 token ID 的稀有程度存在正向关联；同时检查这种画像是否只是词片身份的重复描述。

这是一条可以被否定的描述性假设。关联弱不意味着 feature 路由没有价值；关联强也不意味着路由有效。固定同一词片后的上下文差异只能提示画像含有词片之外的信息，不能直接授予语义功能。

### H2：频率优先后的关系细分

在相同频率段、相同专家数以及匹配成员数/细频率分布的情况下，按 φ 关系形成的子组能在另一批对话中保留额外共现，并使接收输入在原子组成上比随机子组更一致。

组内训练 φ 更高是构造目标，不是验证成功；需要外部复核。输入更一致仍不是学习更好。

### H3：学习价值（后续）

在共享的训练预算与评估规则下，频率优先＋关系细分相对于匹配随机细分取得更好的留出任务表现，并保持原有能力。原始份额选择与常态校准的差异分别评估。

当前分析不填写 H3 结论，不把已有不同设置的结果移作本次结果。

## 五、模型与全部核心量

设 TRAIN 有 N 个有效预测位置，字典有 F 个原子；本模型 F=16,384。

| 符号 | 定义 | 说明 |
|---|---|---|
| x_t | 当前 token 与可见前文 | 不含预测目标及未来文本 |
| v_t | 当前 token ID | 与待预测的 v_(t+1) 分开 |
| h_28(x_t) | 最后一层表征 | 专家实际接收完整 h，不删除 common |
| z_i(x_t) | 冻结 CrossCoder 共享的门控后激活 | 由现有14层联合编码产生，不是14套独立激活 |
| d_28,i | 原子 i 的末层 decoder 向量 | 不再使用14层 decoder 范数之和 |
| A_i(x_t) | 1[z_i(x_t)>0] | 使用现有模型门控，不重新假设每位置 Top256 |
| p_i | TRAIN 上 A_i 的平均值 | feature 命中频率 |
| f(v) | TRAIN 有效位置中当前 ID 为 v 的比例 | token ID 频率，和 p_i 不同 |
| c_i(x) | z_i(x) × ‖d_28,i‖₂ | 末层贡献幅度代理，不是信息量或因果贡献 |
| F_b | 第 b 个频率段的 feature 集合 | TRAIN 固定，低到高排列 |
| M_b(x) | Σ_(i∈F_b)c_i(x) | 该段当前贡献总量，不除成员数 |
| R_b(x) | M_b(x)/Σ_j c_j(x) | 原始贡献份额；零总量记不可估 |
| G_b,k | 频率段 b 的第 k 个内容子组 | 每个原子只在一个子组；Σ_b K_b=K |
| q_i,e | 到达专家 e 的位置中 A_i=1 的比例 | 专家实际接触频率，必须包含 common |
| r_i,e | A_i=1 的位置中到达专家 e 的比例 | 接收率；分母与 q 不同 |

频率段覆盖完整字典：TRAIN 零命中的原子单列为未知频率 U，不强行当作最低频。画像分母保留所有原子的 c；U 在复核文本出现时单独报告其贡献，不能用未来数据重分段。路由只对 TRAIN 已观察频率段竞争；全候选贡献为零时按预定哈希回退并单列统计，不把回退解释为有效路由。

### 主规则：原始贡献优先

1. 选择频率段 b*=argmax_b R_b(x)，等价于 argmax_b M_b(x)。
2. 在该频率段内选 k*=argmax_k Σ_(i∈G_b*,k)c_i(x)。
3. 将完整 h_28(x) 送给专家 (b*,k*)。

第二步也先采用原始贡献，避免尚未讨论就额外加入另一种校准。

### 校准对照

仅替换第一步为 b*=argmax_b M_b(x)/μ_b，其中 μ_b=E_TRAIN[M_b(x)]；第二步及其他设置不变。μ_b 必须有足够支持，零或不可估时报告阻塞，不靠任意小分母制造优势。

这比较的是“绝对贡献最多”与“相对平时最突出”。校准均值相等不保证负载相等。归一化不是首次提出的新机制；本次新增的是单层贡献定义、频率段优先与段内内容细分的明确分工。

### 组内关系

p_ij=E_TRAIN[A_i A_j]；φ_ij=(p_ij−p_i p_j)/sqrt[p_i(1−p_i)p_j(1−p_j)]。

仅在同一频率段内用 φ 做候选细分。p_i 为0或1时 φ 不可定义，必须标注；φ 高不是语义相同，也不是学习梯度一致。即使先分频率段，φ 的边际偏好仍可能残留，所以随机对照还要匹配细频率分布。

## 六、分析路径：按研究者要求的顺序

### 1. 先检验低频 feature 与 token 频率的对应

画当前任务的 feature 频率曲线与频率直方图；计算每位置低频贡献份额。比较不同 token 频率档中的份额分布，再固定同一 token ID 看不同上下文是否变化。必要文本案例由预先规则抽取，不按支持故事挑例子。

回答：画像主要重复词频，还是包含词片身份之外的差异？不能由此直接裁定专家归属。

### 2. 再检查频率分组及关系细分

固定频率段，再比较 φ 子组和匹配随机子组。记录每组成员、p、c，以及各专家的输入文本、实际 q 和接收率 r。检查关系是否在复核对话存在，是否形成了可区分的实际输入组成，common 是否仍大量进入。

回答：名单上的组织在 token 级实际实现了多少？不要只看负载，也不要为了 q 接近而把全部专家都塞同样输入。

### 3. 最后接学习验证

在前两步定义清楚后，使用相同基座与专家结构做有限对照；共同训练预算从 DEV 冻结，TEST 不选轮数。既看答案 NLL，也按任务需要看生成表现。若本次只完成画像与分发，不越级报告学习收益。

## 七、不同结果如何更新认识

| 观察结果 | 可以更新的判断 | 不能推出 | 下一步 |
|---|---|---|---|
| 低频份额与低词频正相关，词片内差异很小 | 画像可能主要重复词片身份 | feature 路由有效 | 增加简单词频路由作为学习对照 |
| 相同词片在不同上下文中有明显份额变化 | 画像含有词片身份之外的差异 | 已识别细腻语义、或预测有用 | 看随机文本实例及可复核输入属性 |
| 词频关联弱或反向 | 撤回正向词频桥梁预测 | feature 无用 | 用实际 feature 组成解释路由，不改口说“其实本来就不该相关” |
| φ 仅TRAIN组内更高，复核不优于匹配随机 | 新增关系证据不足 | 所有关系方法无效 | 不增加此复杂度，保留频率基线 |
| φ 可复现，但实际去向几乎不变 | 关系结构存在，但这套路由未使用其差异 | 关系已经改善学习 | 检查评分是否把子组差别淹没 |
| 接收率提高、q差距仍大 | 送达和专家内频率组织不等价 | common 已经造成损害 | 量化目标富集及共同携带的限制 |
| 实际组织改善，学习无增益 | 当前组织指标不足以保证学习 | 频率永远无用 | 检查训练预算、迁移损失及组成相容性 |
| 组织改善且学习优于匹配对照 | 当前设置支持该规则的增量价值 | 预训练容量倍数 | 再做跨数据/预算复核与成本核算 |
