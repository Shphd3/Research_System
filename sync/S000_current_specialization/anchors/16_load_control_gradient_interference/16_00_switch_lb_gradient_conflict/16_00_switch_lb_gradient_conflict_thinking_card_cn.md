# Thinking Card：负载均衡是否通过梯度冲突减慢有效的 Router 学习？

来源状态：`HUMAN_CONFIRMED`；本文记录研究者在 2026-08-09 批准的研究方向与指标，具体运行参数不属于本卡。

- **父研究方向：** 将负载控制从 A15 频谱路线中独立出来，研究如何在防止专家坍缩的同时，不减慢语言模型学习与专家形成。
- **现象：** 所比较的 Router 都使用同一种 Switch 风格负载均衡系数，但 Vanilla 坍缩、Centered 没有；冻结 DC 审计只定位了公共分量对当前坍缩的即时依赖，没有说明哪一种训练更新形成了该状态。
- **机制判断：** 可微的负载均衡目标可能在 Gate 与 Router 上游参数中注入和语言模型梯度相反的更新；研究者批准以完整全局 batch 上的原始梯度余弦作为机制测量。
- **最强竞争解释：** 局部反向梯度可能是有益正则；真实失败也可能是 soft probability 目标无法改变已经饱和的 hard top-1 赢家。因此负余弦本身不能证明训练受到伤害。
- **改变判断的证据：** 从完全相同的参数和 AdamW 状态出发，对比 LM-only 影子一步与 LM+LB 影子一步。主指标是独立文本上的配对 NLL 差；只有硬负载同时改善且原始 LM/LB 全局 batch 梯度余弦为负，才能解释成有害冲突。
- **最不确定点：** Switch LB 在最早 100M token 内，为其实际实现的负载纠正付出了多大的 held-out 学习代价？
- **当前阻塞：** 在该测量完成前，提高 LB 系数、投影 LB 梯度或改用动态 expert bias 都没有确定的机制归因。
- **为什么现在必须裁定：** 前一条线已经观察到坍缩和明显 centering 收益；若不先分离更新冲突，直接长训会混合负载纠正、正则化、表征几何和系统开销。
- **当前下一决策：** 写出并审核配对的早期梯度—影子更新 Protocol。
- **审计后的研究者首选干预：** 若 A16_00 支持有害梯度冲突或 hard/soft 控制失配，优先测试动态 expert bias；目前它还不是已验证方案。
- **已知材料：** A15 匹配训练、迁入的 DC 维持因素审计、已核验的 Switch 目标、不可变的配对初始化/数据机制，以及辅助损失和无辅助损失负载控制的一手文献。
