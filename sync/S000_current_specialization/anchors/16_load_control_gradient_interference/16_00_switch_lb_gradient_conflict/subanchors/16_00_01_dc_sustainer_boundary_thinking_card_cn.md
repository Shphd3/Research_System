# Thinking Card：为什么相同的负载均衡损失在 Vanilla 中失效？

来源状态：`HUMAN_CONFIRMED`；本文逐项整理研究者在 2026-08-09 审核中明确表达的判断，不补造未确认机制。

- **父研究方向：** A16 研究如何在保持硬专家负载可用的同时，避免负载控制减慢语言模型学习或阻碍专家分化；本卡由 A15 暴露的现象迁入，原始研究者判断保持不变。
- **现象：** 六个训练条件都优化系数为 $0.01$ 的同一种 Switch 风格负载均衡损失，但 Vanilla-Full 的深层几乎把全部 token 送给一个专家，而 Centered-Full 与其他先去中心的频带条件明显更均衡。
- **机制判断：** 未去中心的 Router 输入含有 token 之间共享的均值分量；它经过 Gate 后形成专家特异的固定分数偏置，可能在早期制造很大的赢家 margin。硬 top-1 一旦饱和，基于 soft probability 的负载损失即使数值较大，也可能缺少改变赢家的梯度杠杆。
- **最强竞争解释：** 均值只与坍缩相关；真正原因已经写入 Gate 权重、上游表征或 Router--Expert 反馈，所以对冻结 Vanilla 临时减去真实均值并不能恢复专家使用。
- **最不确定点：** 公共均值项对冻结 Router 的失衡是否同时具有必要性与充分性，还是 centering 只通过更早的训练路径产生作用？
- **改变判断的证据：** 在相同 token 和冻结参数上，Vanilla 减去独立估计的均值后应比随机同幅平移或错误层均值更明显地恢复负载；Centered 加回检查点中心后应重新集中。任一方向失败都要收窄或否定机制。
- **当前阻塞：** 尚不清楚为什么相同的 LB 系数会产生完全不同的硬专家使用。
- **为什么现在必须裁定：** 30B 延长训练需要结合负载与路由动力学解释；在根因未明时直接提高 LB 系数或更换 Router 形式属于无依据修复。
- **当前下一决策：** 双向冻结反事实已经完成并得到 `necessary_only`；父 Anchor A16_00 下一步直接测 LM/LB 全局 batch 梯度与影子一步 held-out NLL，再决定是否进入动态 expert bias。
- **已知材料：** A15_06 E01/E02 结果、已批准的 E03 续训、不可变检查点、冻结统计/验证 token，以及已核验的 Router/LB 实现。
