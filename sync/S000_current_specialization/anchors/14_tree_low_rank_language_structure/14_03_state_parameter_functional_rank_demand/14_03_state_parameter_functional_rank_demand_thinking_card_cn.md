# A14_03 Thinking Card：低共现条件的状态功能秩是否要求更多参数功能方向？

> 状态：根据研究者当前判断重构，等待研究者审核。  
> 作用：决定该问题能否在 A14_02 之后被提升为正式实验问题；本文不是实验结论。

## Human Draft

### 现象

某些低共现的组合推理模式，可能在任务相关的隐藏状态中占用更多独立方向；模型若要可靠处理这些模式，也可能需要更多任务相关的参数方向。

### 机制猜想

高复用模式可以让多个样本共享相同计算方向；低复用模式若包含更多彼此独立的条件关系，其任务状态会更分散，因而需要更大的参数功能子空间维持相同的任务效用。

### 最强竞争解释

观察到的差异可能并非来自“低共现”，而来自以下因素：

- 独立规则或 lookup 数量更多；
- 低频条件尚未被充分训练；
- 参数化冗余使参数谱与状态谱脱钩；
- 网络可通过其他层或算子补偿被限制的参数方向。

### 最不确定的一环

即使 A14_02 观察到任务状态的功能秩差异，也不清楚这种差异是否会因果地要求更多参数功能方向；状态几何和参数容量可能只是相关，而非必要关系。

### 会改变判断的证据

- 若高状态功能秩条件在相同参数秩上限下显著损失任务效用，而增加参数功能秩能够稳定恢复该效用，我会增强这一机制判断。
- 若已经存在稳定状态功能秩差异，但参数秩限制对高、低状态秩条件的影响相同，或增加参数方向不能选择性恢复高秩条件，我会削弱或放弃这一判断。
- 若低共现但共享同一规则的条件仍同时保持低状态功能秩和低参数功能秩，我会拒绝“低共现本身导致更多方向”的表述。

### 当前下一决策

先审核并完成 A14_02 的状态功能秩判定；只有 A14_02 得到稳定、任务充分的状态秩差异后，才决定是否为 A14_03 编写并批准实验协议。

## AI Audit

### 建议收窄后的可裁定问题

不要直接检验“低共现必然高秩”。建议检验：

> 在规则结构、暴露次数、输出分布、模型能力与任务效用匹配后，当一个条件确实需要更高的任务状态功能秩时，保持该条件的任务效用是否也因果地需要更多已注册算子的参数功能方向？

### 需要分别定义的三个对象

- **低共现**：某条确切关系或活动模式在训练数据中的共同出现次数；它不等于长程、低频 token 或高规则复杂度。
- **状态功能秩**：为了保持 held-out 任务效用，根状态至少需要保留的方向数。
- **参数功能秩**：为了保持同一 held-out 任务效用，已注册参数算子至少需要保留的方向数。

### 建议的主判据

先用低状态秩条件确定一个参数秩上限，再把同一上限施加到高状态秩条件：

> 若高状态秩条件承受更大的 held-out 效用损失，并且允许更多参数方向后该损失被恢复，则支持“状态方向需求会转化为参数功能方向需求”。

### 主要边界

- 该结论只能针对预注册的参数算子成立；首先可研究 QK 组合算子，不能外推到全网络。
- 参数谱集中不等于语言表示低秩。
- 即使 A14_03 通过，也不能推出 Router 必须使用更多专家；还需要真实任务上的条件—专家效用证据。
