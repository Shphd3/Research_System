# Results And Artifact Recovery

Start from the named run, Protocol and existing result records. Recover only
requested files and verify identity/completeness. Missing evidence stays
missing; job success is not a result. Status inspection does not authorize a
new analysis or copying a whole run.

Use `experiment-card-writer` for requested Summary/Chinese companion and
Detailed. Summary owns first reading; Detailed owns conformance, deviations,
stage evidence and the artifact map. Separate observation, interpretation,
decision and claim boundary. Only human-confirmed judgment permits a scientific
Anchor/Focus update; result writing does not migrate the artifact layout.

The map links runner/config/code, data manifest, result/figure paths, relevant
checkpoints/logs, repro command, job ID and needed identities/digests. Raw and
generated payloads stay execution-side; dated figures follow root provenance
rules. Finish with verified links and explicit failures/unknowns.

For completed training, register the actual saved checkpoints using the
[asset lifecycle](../../../../assets/README.md#training-and-analysis-lifecycle),
and link their IDs and new access snapshot from the artifact map. Apply the same
lineage rule to reusable representation/SAE-feature caches produced by analysis.
Keep partial/missing saves explicit; catalog completeness is not run success,
resume qualification or scientific support. This does not expand a status-only
request into recovery, new analysis or whole-run copying.

For requested handoff/sync, supply this map and selected research records with
referenced figures to `research-communication`; this skill does not assemble,
publish, commit, push or synchronize the package.
