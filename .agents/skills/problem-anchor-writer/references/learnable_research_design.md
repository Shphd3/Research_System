# Learnable Research Design

Apply only when the active model fits parameters from data. A fixed diagnostic
still needs an evaluation objective but not a fabricated training loss.

Follow data -> task -> objective/constraints -> architecture -> optimization and
selection -> inference and untouched confirmation. Later contradictions reopen
the earliest affected block, not a downstream patch around it.
This is a dependency check, not a mandatory subsection order. Explain why the
data, task and comparison answer the purpose; arrange the text for understanding.

## Scientific Contract

- **Data:** population/generator, example unit, sampling/filtering, transformations,
  candidates, target provenance, selection bias/shift and independent construction
  checks. Distinguish observed input, latent/inferred state, learned parameters
  and output; evaluation truth is not a model input.
- **Task:** permitted inputs, required output, target meaning, prediction unit,
  supervision, refusal/invalid behavior, and why success addresses the question.
- **Objective:** exact optimized quantity, every variable/term/coefficient,
  aggregation, normalization and unit; prior-derived constraints and enforcement.
  Desired invariance and evaluation residuals are not a trainable objective.
- **Architecture:** smallest function family, encoding, components, dimensions,
  capacity/sharing, information flow and inductive bias. State engineering
  baselines separately from scientific mechanisms and name residual failure modes.
- **Optimization:** algorithm class, stopping, admissible selection information,
  inference/decision rule and operating point. Exact schedules/resources belong
  to Protocol, not invented later to complete missing scientific design.

Check collapse, target/identity copying, memorization, scale/gauge/coordinate
ambiguity, future/privileged leakage and dominance from unequal units/counts.
Each relevant shortcut needs a constraint, diagnostic or honest claim restriction.
Do not claim exclusion when it has not been established.

## Information And Computation

Keep `OPERATIONAL`, `TRAIN`, `DEVELOPMENT` and untouched `CONFIRMATION` roles
separate. Targets, pseudo-labels, candidates, fitting, checkpoint selection,
thresholds and per-example decisions may use only permitted information. The
same evidence cannot fit and independently confirm the same claim.

For every objective term/constraint specify its prior, permitted data, exact
operation/enforcement, training signal and separate confirmation evidence. An
independent implementer must not invent a decision-changing design choice.

## Ownership And Completion

Anchor section 2 owns data-process priors; 4 owns variables/task/objective;
5 owns constructible pipeline, architecture, training/inference and stage-local
Goal/How/Why; 6 owns the minimal falsifier. Keep run receipts in Protocol/Detailed.

`PASS` means applicable blocks are explicit and consistent, not scientifically
approved. `FAIL` names the missing or contradictory block; finish independent
work but do not present that design as run-ready. `NOT APPLICABLE` records no
active fitting. User authorization and existing approval boundaries still govern.
