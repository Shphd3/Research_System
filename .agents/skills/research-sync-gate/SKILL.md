# Research Sync Gate

Audit the named account and existing Focus/Anchor/results, not an assumed new
meeting task. Use PROJECTS only to select a workstream. Chat is context; inspect
existing derivations before saying the model is absent.

Check question -> unknown -> credible rival -> distinguishing comparison -> eligible
result or planned outcome -> bounded update -> researcher-owned decision. For a
mechanism, also check objects -> model -> actual change -> consequence and the level
of claim. Separate missing theory, untested factors, incomplete presentation and
unsupported local-to-design inference; use reasoning-auditor for a material gap.

A first-time listener must understand what is studied, changed, predicted, tested
and unresolved. Clearly reported negative or incomplete science can be ready for
discussion. Formal completeness without intelligibility is not readiness.
A reliable boundary result, counterexample, local model or distinguishing new
prediction can be useful meeting material before the full mechanism is settled.

Return `READY_FOR_SYNC`, `READY_FOR_PROTOCOL`, `NEEDS_HUMAN_JUDGMENT` or
`NOT_READY_OBJECT_OR_LOGIC`, with the concrete gap type, source and smallest repair.
These are readiness descriptions, not scientific approval or state transitions.
`NEEDS_HUMAN_JUDGMENT` leaves that decision open; it does not prohibit a labeled
candidate explanation, derivation or proposed test within the request.
Do not reset Focus or redirect the project because an audit found a candidate fix.

A Focus change requires explicit activation, stable problem key and next decision;
then use research-progress-core. Reuse confirmed choices, finish independent audit
while missing judgment stays unknown, and do not add redundant permission gates.
Requested briefs belong to communication, Protocols to experiment-card-writer.
A narrow audit needs no persistent artifact.
