Meeting Brief: Expert-Spectrum Initialization And Early
Route Concentration
Question
这次汇报回答⼀个问题：
上次组会提到的“根据每个 expert 初始化后的主输⼊⽅向，并先处理所有 token 共有⽅向，再做分发”的想法，
能否变成⼀个有效的路由器初始化⽅法？
⽗问题：
真实⽂本中的 top-1 稀疏 MoE 为什么会在训练早期把⼤量 token 分到少数 experts 上？
当前⼦问题：
之前实验发现，即使去掉⾼频 token 的影响，普通⾼斯初始化的线性路由器在第 0 步已经有负载偏置，并且训
练到第 10 步会明显集中。
这次我们测试：
1. 直接⽤ expert 初始化后的主输⼊⽅向初始化路由器；
2. 先去掉 token 共有⽅向后，再⽤ expert 主输⼊⽅向初始化；
3. 只根据初始隐藏表征空间初始化。
我们想判断：这些初始化是否能减少第 0 步偏置，并进⼀步阻⽌第 10 步的路由集中。
这⾥的“主输⼊⽅向”指：每个 expert 初始化参数中，对输⼊最敏感的⼏个⽅向，⽤⼤奇异值对应的输⼊⽅向估
计。
这⾥的“共同⽅向”指：⼀批 token 进⼊路由器前，隐藏表征中⼤家共有的主要⽅向。
Conclusion
⼀句话总结：
我们把上次组会提出的初始化想法做成了⼏个可计算版本；结果显⽰，这种router - 专家对⻬的初始化
能改善第 0 步的分布，但不能阻⽌第 10 步训练放⼤。尽管初始化的时候避免了Router对⻬Common⽅
向形成负载集中，但是训练中图Router还是存在Router越来越对⻬Common⽅向。
1. 初始化可⾏性：expert 初始化后的主输⼊⽅向存在差异，并且和表征空间共同⽅向不同。因此能够使得
step 0 的负载集中现象减缓
我们⽤每个 expert 的输⼊矩阵估计主输⼊⽅向。不同 experts 的主⼦空间平均重合约 0.0116，说明随机
初始化后的 experts 在参数⽅向上确实有差异。它们与隐藏表征共同⽅向的平均重合约 0.0166，说明这
些⽅向不是简单等同于共同⽅向。
这说明：上次组会提出的“按 expert 初始化⽅向来分发”的想法有计算基础，值得测试。
但这还不能说明：expert 在初始化时已经形成了有任务意义的分⼯。
2. ⽅法层⾯：去掉共同⽅向后的初始化能改善第 0 步，但不能改善第 10 步。
去掉共同⽅向后的初始化，确实让第 0 步 token 分布更接近均匀。去掉前 1% ⾼频 token 后，普通随机
初始化的第 0 步最⼤ expert 负载是 19.98%，去共同⽅向版本是 13.97%。

3. 机制层⾯：第 10 步集中不能只靠初始化解释，⽽要看路由器和隐藏表征在训练中的共同变化。
Anchor2 的训练过程审核显⽰：第 10 步集中不是单纯因为路由器权重⾃⼰变了，也不是单纯因为隐藏表

因此，这次初始化实验失败的主要解释不是“expert 主输⼊⽅向完全没有⽤”，⽽是：当前线性初始化版

Key Evidence
1. expert 主⼦空间差异是可测的。
不同 experts 的主⼦空间平均重合约 0.0116，说明它们在初始化后不是同⼀组⽅向。
2. expert 主⼦空间不是 hidden state 的共同⽅向本⾝。
expert 主⼦空间与共同⽅向⼦空间的平均重合约 0.0166。这说明 raw spectrum 失败不是因为 expert 主
⼦空间本⾝直接就是共同⽅向。
3. expert 主⼦空间与强制路由效⽤有弱相关。
raw spectrum 版本的残差谱分数与强制路由效⽤相关约 0.2328，⾼于 random 的 0.0952；top-1 效⽤
匹配约 0.3889，⾼于 random 的 0.2222。
4. 当前实现桥很弱。
residual-spectrum oracle 分配很均匀，max load 约 0.144，有效 experts 约 7.96；但压成线性 router
后，oracle-to-linear agreement 只有约 0.20--0.25。这说明⼦空间投影分数很难直接由当前线性 top-1
router 表达。
5. common-filtered 初始化改善第 0 步，但第 10 步失败。
去掉前 1% ⾼频 token 后，late layers 第 0 步 rank-1 expert 负载：random 19.98%，common-filtered
13.97%。
第 10 步 rank-1 expert 负载：random 83.16%，common-filtered 93.51%。
6. 完整训练指标不⽀持⽅法结论。
late layers 平均：random 的 step-10 max load 为 0.8344，common-filtered 为 0.9374；random 的
effective experts 为 1.5636，common-filtered 为 1.2177。common-filtered 降低了⼀部分耦合项，但
没有降低最终集中。
7. Anchor2 显⽰第 10 步集中不是单⼀因素造成。
第 5 层 cross-checkpoint replay 中，gate-only 贡献为 -0.0137，hidden-only 贡献为 0.4858，
interaction 为 0.8038。这说明只看 router 更新或只看 hidden state 漂移都不够，⼆者共同变化后的相
互作⽤很重要。

Current Interpretation
之前组会提到的⽅法可以这样理解：
expert 初始化后不是完全⼀样的，所以 router 初始化不应完全随机；它应考虑 expert 参数中的主输⼊
⽅向。
这⾥有两个版本：
1. 初始版：直接⽤各 expert 的⼤奇异值主⽅向和 token 表征做匹配，再决定分发。
2. 修正版：先把所有 token 共享的共同⽅向去掉，再⽤剩余⽅向和 expert 主⼦空间做匹配。
这次实现的是修正版中的“去共同⽅向”版本；我们没有显式加⼊⼀个 common expert，⽽是先估计共同⽅向⼦
空间，再把相关投影从初始化计算中去掉。

我们的实验把这个⽅法推进了⼀步：
这个⽅法在计算上可以定义，⽽且 expert 主⼦空间差异与强制路由效⽤有弱相关；但直接落到当前线性
top-1 router 上，还不能形成成功⽅法。
关键解释是：
1. 第 0 步改善有证据⽀持。 common-filtered 初始化减少了初始负载偏置。
2. 第 10 步失败也有证据⽀持。 训练很快把 token 重新集中到少数 experts。
3. 所以瓶颈不只是初始化分布。 早期 hidden state 变化、router 与共同⽅向的对⻬、以及⼆者共同变化后
的相互作⽤仍然存在。
因此，这次结果不是“之前组会提到的⽅法不成⽴”，⽽是：
这个方法的线性实现还不够。
更大的问题是训练前 10 步会把初始偏置继续放大。
Boundary
现在可以说：
1. expert 主⼦空间之间存在可测差异，与 hidden state 共同⽅向重合低，并且与强制路由效⽤有弱相关。
2. common-filtered 初始化能改善第 0 步负载分布。
3. 当前线性 top-1 router 初始化不能阻⽌第 10 步早期集中。
4. 仅仅让第 0 步更均匀，不等于解决 early route concentration。
5. ⾼频 token 不是第 0 步初始化差异的主要解释。
现在不能说：
1. 专家谱没有⽤。
2. 之前组会提到的⽅法不成⽴。
3. oracle router、⼆次 router 或 learned classifier router 也会失败。
4. 结果能推⼴到预训练⼤模型、top-2/top-4 MoE 或带负载均衡损失的训练。
5. 我们已经解释了最终 expert specialization。
Next Step
不建议继续只扩⼤当前线性初始化实验。
下⼀步应先回答⼀个主问题，再保留⼀个分⽀问题。
