# Chapter IV: Hypothesis - 重点学习版

说明：本文不是第四章逐段全文翻译，而是面向当前科研训练目的的中文改写、解析和学习路线。重点是理解“假设如何推动实验、如何暴露错误、如何通向新方法”。

## 1. 本章一句话结论

假设是研究者最重要的智力工具；它的价值不在于一开始就正确，而在于能不能生成新的观察、实验和可区分的预测。

对我当前最重要的理解：

> 好假设不是让我“相信一个解释”，而是让我知道下一步该做哪个实验。

## 2. 本章在全书中的位置

前言强调：科研最重要的仪器是研究者的头脑。

第四章进一步说明：这个“头脑”不是泛泛聪明，而是能做三件事：

- 把模糊现象压缩成假设；
- 用假设生成实验；
- 在事实反对时修改或放弃假设。

这正对应我现在缺的能力：从真实模型现象中抽象变量、建立解释、构造实验、最后形成方法。

## 3. 作者的核心观点

### 3.1 假设的主要用途不是证明自己

作者认为，假设最重要的功能是提出新的实验和观察。

一个假设应该像工具，而不是结论。它可以是暂时的、错误的、不完整的，但只要它能推动实验，它就有研究价值。

对我的启发：

- 不要把假设写成“我认为一定是 X”；
- 应该写成“如果 X 是主要机制，那么应该观察到 A；如果 rival explanation Y 是主要机制，那么应该观察到 B”。

### 3.2 错误假设也可能产生发现

第四章列举了很多例子：研究者最初的解释是错的，但这个错误解释引导他们做出了关键实验，最后发现了真正的现象。

这些例子的共同结构是：

1. 研究者看到一个未解释现象；
2. 提出一个可能解释；
3. 按这个解释设计实验；
4. 实验结果不完全符合原假设；
5. 研究者没有停在失败，而是追踪异常；
6. 异常反而揭示了新机制。

关键不是“错也无所谓”，而是：

> 错误假设如果能迫使世界给出反馈，也比没有假设更有生产力。

### 3.3 假设会帮助观察者看见有意义的事实

同一个现象，没有假设的人可能看不出意义；带着假设的人会知道哪些细节值得注意。

这说明观察不是被动看数据，而是“在一个解释框架下识别异常”。

对我当前研究的对应：

- 如果我只看 router accuracy、bucket utilization、loss，很可能错过真正机制；
- 如果我的假设是“router boundary 是否对齐 feature-separating direction”，我就会去看 hidden space、router projection、PCA direction、feature identity 的关系。

### 3.4 假设不能被过度保护

作者强调一个危险：提出假设后，研究者会对它产生“亲子式偏爱”。这会导致：

- 忽略反例；
- 只记录支持性现象；
- 用越来越多 ad hoc 补丁保护主假设；
- 把实验失败解释成技术问题，而不是假设问题。

对我的警告：

如果一个假设需要越来越复杂的附加解释才能活下去，它可能已经不再是好假设。

### 3.5 不要过早放弃，也不要顽固坚持

作者区分了两种情况：

- 如果实验结果直接反对假设，并且需要牵强补丁才能解释，应该放弃或重构假设。
- 如果只是暂时没有验证成功，但没有直接反证，可能需要继续尝试、换技术、换条件。

这对实验科研很关键。负结果不自动等于假设错，可能是：

- 测量指标不对；
- 实验条件不对；
- 干预太弱；
- 数据构造没有击中机制；
- 当前技术还不足以验证。

但如果多个条件下都系统性反对假设，就不能继续把它当主线。

## 4. 本章主要例子的压缩理解

### 4.1 哥伦布例子：错误目标也可能打开新世界

哥伦布想通过向西航行到达东方，但实际发现了新大陆。

研究启发：

- 研究者可能带着错误目标出发；
- 但如果行动足够具体，世界会暴露新事实；
- 真正的问题是能否识别“发现的东西不是原来想找的东西”。

### 4.2 白喉毒素例子：坚持有时必要

研究者假设白喉杆菌通过毒素致死，早期实验失败，但继续调整条件后找到证据。

研究启发：

- 失败不一定说明假设错；
- 如果假设有强机制动机，且没有直接反证，可以继续优化实验；
- 但坚持必须伴随条件分析，而不是盲目重复。

### 4.3 Claude Bernard 例子：错误预测引出新机制

Bernard 预期切断某神经会让兔耳变冷，结果变热，从而引出血管受神经控制的发现。

研究启发：

- 反方向结果不是垃圾结果；
- 它可能说明原假设中的因果方向、控制变量或中间机制错了；
- 关键是把“意外”转化为新的变量关系。

### 4.4 Milk fever 例子：错误解释也可能产生有效干预

治疗方法最初建立在错误机制解释上，但实际产生了治疗效果。

研究启发：

- 有效方法不等于机制解释正确；
- 方法论文不能只证明“有效”，还要小心说明“为什么有效”是否已经被支持；
- 经验有效性和机制理解是两层 claim。

### 4.5 Ehrlich 例子：强假设能组织长期搜索

Ehrlich 的化疗设想部分错误，但它组织了系统搜索，最后推动药物发现。

研究启发：

- 好假设可以成为搜索原则；
- 即使细节机制错，搜索空间被合理约束后仍可能产生方法；
- 方法创造常常来自“把巨大空间压缩成一个可搜索方向”。

## 5. 和“数学建模”的关系

第四章没有直接教数学建模，但它给出了数学建模的科研用途：

> 建模的目的不是写漂亮公式，而是把模糊现象变成可检验、可反驳、可干预的假设。

我当前应把数学建模理解为六步：

1. **对象化**：研究对象是什么？例如 token、hidden state、router logit、expert choice、attention mass。
2. **变量化**：哪些量代表对象状态？例如 $h_t$、expert id、feature identity、loss、attention top-k mass。
3. **关系化**：变量之间被假设有什么关系？
4. **竞争解释化**：还有哪些 rival explanations 能解释同一现象？
5. **预测化**：不同解释分别预测什么可观测结果？
6. **实验化**：哪个最小实验能让预测分开？

如果一个“数学建模”不能导出第 5 和第 6 步，它还只是表述，不是研究工具。

## 6. 实验和假设的目的

实验和假设不只是为了“加深理解”。更准确地说，它们有四个目的：

### 6.1 缩小不确定性

从“我不知道为什么”变成：

- 不是 A；
- B 解释更强；
- C 仍未排除；
- 下一步必须区分 B 和 C。

### 6.2 区分竞争解释

一个实验如果不能区分 rival explanations，就算结果漂亮，也未必推进主线。

对我当前研究尤其重要：

- router 行为可能由 feature identity 决定；
- 也可能由 token shortcut 决定；
- 也可能由 hidden norm、confidence、loss 或 PCA direction 决定；
- 实验价值在于让这些解释产生不同预测。

### 6.3 找到可干预变量

理解要变成方法，必须找到可干预变量。

例如：

- 如果失败来自 router input 没有检索相关信息，那么方法方向是增强表示；
- 如果信息存在但 router boundary 没对齐，那么方法方向是改变 routing objective 或边界约束；
- 如果 dense attention 追踪的是 value/output similarity，那么方法方向应改为 value-predictive retrieval，而不是 feature/expert indexing。

### 6.4 形成设计原则

新方法不是从“我更理解了”自动产生，而是从下面这条链产生：

现象 -> 假设 -> rival explanations -> 最小实验 -> 可干预失败机制 -> 方法原则 -> 算法设计。

## 7. 对我当前研究的直接映射

### 7.1 当前现象

已有现象可以压缩为：

router / MoE / H-MoE bucket 没有比 random matched candidates 更好地恢复 dense attention high-mass KV。

这只是结果，不是解释。

### 7.2 可建模对象

- 查询位置的 hidden state：$h_t$
- 候选 KV 的表示：$k_i, v_i$
- dense attention mass：$a_{t,i}$
- router logits：$r_t$
- expert choice：$e_t$
- feature identity 或 context relation：$z_t$
- retrieval-relevant variable：$u_t$

### 7.3 主假设示例

主假设不是“router 不行”，而应写成：

> retrieval-relevant information 存在于 hidden state 中，但当前 router objective 没有迫使 router boundary 对齐该信息。

### 7.4 Rival explanations

至少要保留这些竞争解释：

1. hidden state 中根本没有足够的 retrieval-relevant information；
2. 信息存在，但 router projection 没有读出它；
3. router 读出的是 token shortcut，而不是 feature relation；
4. router 读出的是 loss/confidence/hidden norm，而不是语义或检索变量；
5. dense attention high-mass KV 本身不由 feature identity 决定，而由 value/output similarity 或其他变量决定。

### 7.5 最小实验的目的

实验不是为了堆更多结果，而是为了回答：

> 哪个变量最能解释 router choice 或 attention high-mass candidate？

如果答案明确，就能导向方法：

- 如果是 feature relation：设计 feature-aware routing。
- 如果是 value similarity：设计 value-predictive KV retrieval。
- 如果是 hidden norm/confidence：说明 router 可能在学难度或置信度分配，而不是检索结构。
- 如果是 projection boundary 问题：设计 boundary alignment loss。

## 8. 第四章给我的方法构造原则

### 原则 1：不要从方法开始，要从失败机制开始

弱问题：

> 我能不能设计一个更好的 router？

强问题：

> 当前 router 失败是因为缺少信息、读出方向错、训练目标错，还是 dense attention 追踪的对象与 expert specialization 不一致？

### 原则 2：每个方法必须对应一个被定位的机制缺陷

方法不是凭空造出来的。方法应该是对失败机制的干预。

例子：

- 失败机制：router boundary 不对齐 feature direction。
- 方法原则：给 router 一个对齐 feature direction 的训练信号。
- 算法形式：auxiliary boundary alignment loss、contrastive routing objective、feature-pair supervision 等。

### 原则 3：理解必须落到“如果我改 X，会发生 Y”

如果理解不能产生干预预测，它还不能变成方法。

可用模板：

> 如果机制 M 是瓶颈，那么干预变量 X 应该改善指标 Y；如果没有改善，说明 M 不是主要瓶颈或干预没有击中机制。

### 原则 4：不要只证明方法有效，还要证明为什么不是别的原因

一个方法有效后，还要排除：

- 参数量变大；
- training budget 变多；
- regularization 效应；
- 数据泄漏或 shortcut；
- 指标选择偏差；
- 只在 toy setup 上成立。

## 9. 本章应重点学习什么

我不需要把第四章当历史故事读。应重点学习四个动作：

1. **把假设当工具**：它要服务于下一步实验。
2. **保留 rival explanations**：不要让单一解释绑架观察。
3. **追踪异常结果**：反方向结果可能比符合预期更有价值。
4. **从机制缺陷走向方法**：新方法来自可干预失败机制。

## 10. 阅读时的自检问题

读第四章时，每读完一个例子，问：

1. 原始假设是什么？
2. 它预测了什么？
3. 实验结果支持、反对，还是偏离了预测？
4. 研究者有没有抓住偏离？
5. 新发现来自原假设正确，还是来自追踪错误？
6. 如果换成我的研究，哪个异常结果值得被追踪？

## 11. 我的六行假设卡模板

以后每个研究想法先写成六行：

### 现象

我直接观察到了什么？

### 对象

我要解释哪个对象的行为？

### 变量

哪些变量可能决定这个行为？

### 主假设

我认为主要机制是什么？

### Rival explanations

还有哪些解释也能解释同一现象？

### 最小区分实验

哪个实验能让主假设和 rival explanations 产生不同预测？

## 12. 当前学习结论

第四章对我的核心帮助不是提供具体算法，而是纠正研究动作：

- 假设不是故事装饰，而是实验生成器；
- 实验不是结果收集器，而是解释区分器；
- 理解不是终点，找到可干预机制才是方法创造的起点；
- 新方法不是凭灵感出现，而是从“被定位的失败机制”中长出来。

## 13. Claim Boundary

这份笔记能支持：

- 用第四章训练假设意识；
- 把数学建模理解为变量、关系、rival explanation 和实验预测的组织；
- 把“理解现象”推进到“定位可干预失败机制”。

这份笔记不能支持：

- 直接给出一个新的 router / KV retrieval 方法；
- 证明当前 active project 的具体机制已经明确；
- 替代对实验结果和代码 artifact 的正式分析。

## 14. 下一步

下一步不要继续泛读整本书。建议把当前研究中的一个真实现象写成六行假设卡，然后用第四章的方法检查：

- 主假设是否能产生预测；
- rival explanations 是否足够强；
- 最小实验是否真的能区分解释；
- 若区分成功，能否导出一个可干预方法原则。
